## 一、DNS（域名系统）

### 1. 层次结构

```
根域名服务器 (13个逻辑标识 A-M，通过任播部署大量实例)
├── 顶级域名服务器 (TLD): .com, .cn, .org, .edu
│   └── 权威域名服务器: 各组织自己维护

（层次树之外）本地域名服务器 = 递归解析器
   → 它是主机首先询问的解析服务，不是命名层次中的权威一级
```

### 2. 查询方式

| 方式 | 过程 | 负载方 |
|------|------|--------|
| **递归查询** | 被查询服务器负责返回最终答案或明确失败，而不是只返回下一步转介；典型场景是主机请求本地 DNS 递归解析 | **提供递归服务的服务器负担重** |
| **迭代查询** | 被查询服务器向查询者**返回转介**（下一步去问谁），逐级指路；典型情况由本地 DNS 继续迭代 | **根/TLD负担轻** |

> 典型流程（408 常见模型）：
> **主机 → 本地DNS(递归) → 根(迭代) → TLD(迭代) → 权威(迭代) → 返回**
> 主机只发一次请求（递归给本地DNS），本地DNS 再迭代询问各级服务器。

### 3. DNS缓存

- 本地DNS服务器缓存结果（有TTL）
- 浏览器、操作系统（本机）也有DNS缓存
- 缓存可减轻根/TLD压力
- 408 常见缓存位置：浏览器 → 操作系统 → 本地DNS（由近到远）

### 4. DNS报文

> 使用 **UDP 53**（大多数查询）
> 区域传输通常用 **TCP 53**；只要 UDP 响应设置截断标志，就可能改用 TCP（与是否启用 EDNS 无必然互斥）

| 字段 | 说明 |
|------|------|
| 标识符 | 匹配请求和响应 |
| 标志 | QR(查询/响应)、AA(权威)、RD(期望递归)、RA(可用递归) |
| 问题数/回答数/权威数/附加数 | 4个计数字段 |

### 5. 常见资源记录（RR）

| 记录 | 含义 |
|------|------|
| **A** | 域名 → IPv4 地址 |
| **AAAA** | 域名 → IPv6 地址 |
| **NS** | 域的权威域名服务器 |
| **CNAME** | 别名 → 规范名 |
| **MX** | 邮件交换服务器（优先级数字小的优先）|

## 二、HTTP/HTTPS

### 1. HTTP连接方式

| 方式 | 特点 | 每个对象连接数 |
|------|------|:-----------:|
| **非持久连接** | 每个对象一个TCP连接 | N个对象= N次TCP |
| **持久连接（HTTP 1.1默认）** | 同一连接传多个对象（限定同一服务器且连接未被关闭） | 1次TCP |
| **流水线** | 不等待响应连续发送请求 | 1次TCP，请求连续发 |

> HTTP 1.0 默认非持久；HTTP 1.1 默认持久（支持流水线，但**不默认启用**，现代浏览器普遍停用 pipelining）

### 2. HTTP报文结构

**请求报文：**
```
方法 URL 版本
首部字段名: 值
(空行)
实体主体（部分方法可有，如 POST/PUT/PATCH）
```

**响应报文：**
```
版本 状态码 短语
首部字段名: 值
(空行)
实体主体
```

### 3. 方法

| 方法 | 用途 |
|------|------|
| GET | 请求资源 |
| POST | 提交数据 |
| HEAD | 请求响应首部（不返回实体）|
| PUT | 用请求内容创建或整体替换目标资源（上传文件只是常见用途） |
| DELETE | 请求删除目标资源的当前关联（目标不一定是文件） |

### 4. 状态码

| 状态码 | 含义 |
|:-----:|------|
| 1xx | 信息性 |
| 2xx | 成功（200 OK） |
| 3xx | 重定向（301 永久迁移, 302 临时） |
| 4xx | 客户端错误（404 未找到） |
| 5xx | 服务器错误（503 服务不可用）|

### 5. Cookie

```
用户 ←→ 浏览器 ←Cookie→ 服务器

Cookie用途：
- 身份识别
- 会话管理
- 个性化推荐
```

### 6. 缓存

| 机制 | 说明 |
|------|------|
| **强缓存** | Expires / Cache-Control: max-age，未过期直接用 |
| **协商缓存** | Last-Modified / ETag → 304 Not Modified |

### 7. HTTPS

> HTTPS 是受 TLS 保护的 HTTP：HTTP/1.1、2 通常使用 TCP + TLS，HTTP/3 使用集成 TLS 1.3 的 QUIC/UDP；默认端口 443。

```
HTTPS握手（旧式 TLS_RSA 简化流程，⚠️ 教学示例）：
① 客户端发支持的加密套件+随机数
② 服务器返回证书+选定的加密套件+随机数
③ 客户端验证证书，生成预主密钥，用服务器公钥加密发送
④ 双方用客户端随机数+服务器随机数+预主密钥 → KDF 派生会话密钥
⑤ 之后通信用会话密钥对称加密（TLS 同时提供完整性/认证保护）

⚠️ 版本：③④ 是旧式 TLS_RSA 密钥传输；TLS 1.3 已取消 RSA 密钥传输，
  改用 (EC)DHE——现代 TLS 题不要答"服务器公钥加密预主密钥"。
```

### 8. HTTP版本对比

| 版本 | 特点 |
|:---:|------|
| 1.0 | 非持久，每个对象一个TCP |
| 1.1 | 默认持久；支持但不默认启用流水线；Host首部、块传输 |
| 2.0 | 多路复用、二进制分帧、服务器推送、首部压缩 |
| 3.0 | 基于QUIC（UDP），恢复连接可 0-RTT（首次连接仍需握手） |

### 9. HTTP RTT 速算

> 统一口径：`N` 为对象总数（含基础 HTML）；忽略 DNS、TLS、发送时延和拥塞窗口限制；持久连接要求对象位于可复用的同一连接上。

| 模式 | 从首次建立 TCP 连接计时 | 首个连接已建立后计时 |
|---|:---:|:---:|
| 非持久、串行 | `2N RTT` | `(2N-1) RTT` |
| 持久、非流水线 | `(N+1) RTT` | `N RTT` |
| 持久、流水线（`N>=2`） | `3 RTT` | `2 RTT` |

`N=1` 时没有嵌入对象，持久连接两列分别为 `2 RTT`、`1 RTT`。DNS 时延需另加；跨服务器资源通常不能复用原连接。题目给出 MSS、文件大小或慢开始时，必须按 TCP 发送轮次计算，不能直接套表。

## 三、FTP（文件传输协议）

### 1. 双连接

| 连接 | 持续时间/建立时机 | 端口 |
|------|-----------------|:---:|
| **控制连接** | 整个会话保持 | TCP **21**（客户端主动连服务器） |
| **数据连接** | 传输文件时创建，传输完关闭 | 主动：服务器源端口 **20**；被动：服务器临时端口 |

### 2. 两种模式

| 模式 | 数据连接建立方式 |
|------|----------------|
| **主动模式（PORT）** | 客户端通过 PORT 命令告知自己监听的数据端口；服务器以**自己的 TCP 20 为源端口**主动连接客户端声明的数据端口 |
| **被动模式（PASV）** | 服务器开放一个高位临时端口并告知客户端；**客户端主动连接**该端口 |

> 注意：20 是服务器数据连接的**源端口**，不是客户端数据端口。
> 防火墙环境下常用被动模式（服务器不主动连客户端）。

### 3. 特点

- 控制连接带外传输（out-of-band）
- 服务器保留状态（跟踪用户当前位置）
- 用户名/密码认证

## 四、电子邮件

### 1. 体系结构

```
用户代理(UA) --SMTP--> 发送方服务器 --SMTP--> 接收方服务器 <--POP3/IMAP-- 用户代理(UA)
    Outlook                                      接收端             Outlook
```
> 发送方向用 SMTP（单向推）；取信用 POP3/IMAP（单向拉）。

### 2. 协议对比

| 协议 | 端口 | 作用 | 特点 |
|------|:---:|------|------|
| **SMTP** | 25 | 发送/转发邮件 | 推协议(push)，7位ASCII，不能直接传二进制→需 MIME 封装，再经 base64（或 quoted-printable 等）内容传输编码转 ASCII |
| **POP3** | 110 | 接收邮件（下载） | 拉协议(pull)，支持下载并删除/下载并保留（由客户端配置决定） |
| **IMAP** | 143 | 接收邮件（在线操作） | 拉协议，邮件保留服务器，管理文件夹 |
| **MIME** | — | 定义邮件内容类型/封装扩展 | 让 SMTP 能承载非 ASCII 内容；base64 负责把二进制编码成 ASCII 文本 |

### 3. SMTP vs HTTP

| 特性 | SMTP | HTTP |
|------|------|------|
| 方向 | 推(push) | 拉(pull) |
| 格式 | 7位ASCII | 可承载任意字节，用 Content-Type 等 MIME 风格首部描述媒体类型 |
| 连接 | 持续 | 可根据版本不同 |
| 状态码 | 3位数字 | 3位数字 |

### 4. 邮件格式与基于 Web 的电子邮件

```text
基本邮件格式 = 首部 + 空行 + 主体
常见首部：From、To、Subject；MIME 增加 Content-Type 等字段以描述附件和非 ASCII 内容

Web 邮件：浏览器 ↔ 邮件系统使用 HTTP/HTTPS
邮件服务器 ↔ 邮件服务器仍使用 SMTP
IMAP 是邮件访问协议，不等同于基于 Web 的电子邮件
```

## 五、DHCP（跨层扩展：动态主机配置协议）

### 1. DORA过程

```
① Discover（广播）: "谁有IP给我？"
② Offer（可选广播/单播）: "我用这个IP给你"
③ Request（广播）: "我要用这个IP"
④ ACK（可选广播/单播）: "确认，你可以用"
```

### 2. 关键点

| 点 | 说明 |
|---|------|
| 端口 | **服务器 67，客户端 68**（别记反） |
| 传输层 | UDP |
| 地址租期 | 到期需续约 |
| 跨网段 | 需要DHCP中继代理（relay agent）|

> 考题：DHCP用广播请求，因为客户端此时还没有IP地址

## 八、网络应用模型（C/S 与 P2P，408 考点）

| 对比 | C/S（客户-服务器） | P2P（对等） |
|------|-------------------|-------------|
| 角色 | 客户端请求、服务器响应，角色固定 | 每节点既是客户端也是服务器，角色对等 |
| 扩展性 | 服务器是容量瓶颈，用户多会变慢 | 节点越多总资源越丰富，自扩展 |
| 单点故障 | 服务器故障影响全局（可用集群/负载均衡缓解） | 无中心时无单点故障；有中心索引/Tracker 时索引仍是单点 |
| 典型应用 | Web、Email | BitTorrent、区块链 |

P2P 三种实现（重点）：

```text
集中式：中心索引服务器记录"谁有什么"，Peer 之间直传（Napster）
        ← 注意：有中心索引，索引服务器可能成为单点故障
完全分布式：无中心，查询靠广播/邻居转发（Gnutella）
混合式：有 Tracker 索引，传输是 P2P（BitTorrent）
```

> 注意：P2P 不等于"没有服务器"——集中式/混合式仍有索引服务器；
> "节点越多越快"也不是绝对（还受上传带宽、在线率影响）。

## 九、WWW 与 URL（408 主干）

```text
WWW 组成（C/S 模型）：
  Web 客户端（浏览器） + Web 服务器 + URL 统一资源定位符
  网页 = 由多个对象（HTML 文件、图像、视频等）组成，每个对象有 URL
  HTTP/HTTPS 负责客户端与服务器之间传输对象；HTML 用标记和超链接组织网页内容

URL 组成（4 部分）：
  <协议>://<主机>:<端口>/<路径>
  例：http://www.example.com:80/index.html
   协议 http  主机 www.example.com  端口 80（默认可省略）  路径 /index.html
  作用：标识或定位 Internet 上的资源（同一资源可能有多个 URL）

基于万维网的电子邮件：
  浏览器与邮件系统之间用 HTTP/HTTPS 收发邮件（区别于 UA 直连 SMTP/POP3）
```

## 十、选择题高频陷阱

| 陷阱说法 | 纠正 |
|---------|------|
| DNS 使用 TCP 53 | ◐ 大多数查询用 UDP 53；UDP 响应设置截断标志时可改用 TCP，区域传送通常用 TCP |
| 根域名服务器存储所有域名映射 | ✗ 根区保存**顶级域的委派信息**（NS 记录及必要 glue 记录），不存储具体域名 |
| 递归查询比迭代查询快 | 不一定；递归/迭代描述查询责任与返回方式，快慢取决于缓存、链路和服务器状态 |
| HTTP 1.0默认持久连接 | ✗ HTTP 1.0默认**非持久** |
| FTP数据连接一直保持 | ✗ 控制连接保持，数据连接每次传输新建 |
| SMTP直接传二进制文件 | ✗ 408 传统 SMTP 模型传 7 位 ASCII；MIME 负责封装与声明，二进制常用 base64/quoted-printable 等内容传输编码 |
| POP3 邮件一定保留在服务器 | ✗ POP3 下载后删除/保留由**客户端配置决定**（IMAP 典型保留在服务器） |
| DHCP客户端端口67，服务器68 | ✗ 是**服务器 67、客户端 68**（别记反！） |
| RIP是网络层协议 | ✗ RIP是应用层协议（基于UDP 520） |
| HTTP/1.1 默认启用流水线 | ✗ 默认**持久连接**，流水线只是支持、不默认启用 |
