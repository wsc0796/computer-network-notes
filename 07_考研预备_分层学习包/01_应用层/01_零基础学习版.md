## 1. 应用层解决什么问题

应用层是最靠近用户的一层，它直接为具体网络应用提供服务。

规定应用进程在通信时所遵循的协议
可以先这样理解：

```text
应用层协议 = 应用程序之间约定好的说话规则。
```

比如：

| 应用场景 | 协议 |
|---|---|
| 浏览网页 | HTTP/HTTPS |
| 域名解析 | DNS |
| 文件传输 | FTP |
| 发送邮件 | SMTP |
| 接收邮件 | POP3/IMAP |

## 2. 应用层学习主线

应用层要抓这条线：

```text
用户要使用网络服务
    ↓
应用进程之间需要通信规则
    ↓
形成各种应用层协议
    ↓
应用层协议依赖运输层 TCP/UDP 传输数据
```

## 2.5 408 主干一览（每个协议先记骨架，细节见 07_考研强化速查.md）

```text
DNS：层次（根/TLD/权威 + 层次外的本地DNS）→ 递归/迭代查询 → 缓存（浏览器/OS/本地DNS）→ UDP 53
HTTP：请求-响应 → 非持久（每对象一连接）vs 持久（复用连接）→ 流水线 → 报文结构 → 状态码
FTP：双连接（控制21保持 + 数据按需新建）→ 主动（服务器连客户端，源端口20）/被动（服务器临时端口）
邮件：SMTP 推（25）+ POP3（110）/IMAP（143）拉 → MIME 封装非 ASCII（base64 等编码）
网络模型：C/S（客户端请求、服务器响应）vs P2P（节点对等，集中式/完全分布式/混合式）
```

> 以上五个骨架是应用层 408 主干命题的出发点，先背骨架再做 04_题型训练.md。

记忆：

```text
HTTP 负责网页怎么请求和响应。
DNS 负责域名变 IP。
FTP 负责文件传输。
SMTP/POP3/IMAP 负责邮件。
```

## 3. HTTP 与 HTTPS

WWW 是基于 C/S 模型的分布式超文本系统：浏览器通过超链接访问 Web 服务器上的 HTML、图片、脚本等对象，每个对象都由 URL 定位。

```text
URL 基本形式：协议://主机:端口/路径
例：http://www.example.com:80/index.html
协议=http，主机=www.example.com，端口=80，路径=/index.html
```

HTTP 是超文本传输协议，负责浏览器和 Web 服务器之间的请求与响应。

HTTP 特点：

```text
默认端口 80
无状态
请求-响应模式
HTTP/1.x、HTTP/2 基于 TCP；HTTP/3 基于集成 TLS 1.3 的 QUIC/UDP
HTTP 本身不提供安全机制；明文 HTTP 不加密，HTTPS 使用 TLS 保护传输
```

HTTPS 可以理解为：

```text
HTTPS = HTTP + TLS/SSL
```

HTTPS 特点：

```text
默认端口 443
加密传输
身份认证
完整性保护
```

为什么 HTTP 是无状态的：

```text
服务器不会天然记住前后两次请求属于同一个用户。
如果需要保持状态，通常借助 Cookie、Session、Token 等机制。
```

## 4. DNS

DNS 的作用：

```text
把域名解析成 IP 地址。
```

例如：

```text
www.example.com -> 某个服务器 IP
```

DNS 常用 UDP，端口 53。区域传送等场景可能用 TCP。

DNS 命名层次：

```text
根域名服务器 -> 顶级域名服务器（TLD）-> 权威域名服务器
本地域名服务器位于命名层次之外，是主机首先询问的递归解析器。
```

浏览器、操作系统和本地域名服务器都可能缓存解析结果；缓存记录受 TTL 限制，命中时可减少查询次数和时延。

DNS 查询方式：

| 查询方式 | 含义 |
|---|---|
| 递归查询 | 客户端把任务交给 DNS 服务器，由服务器继续查到底 |
| 迭代查询 | 被查询服务器向查询者返回答案或转介；典型情况下由本地 DNS 继续逐级查询 |

## 5. FTP

FTP 用于文件传输。

重要特点：

```text
FTP 使用两个 TCP 连接。
控制连接：传输命令，常用 21 端口。
数据连接：传输文件数据。
```

为什么是双连接：

```text
命令控制和数据传输分开，便于边传文件边保持控制会话。
```

## 6. 邮件协议

典型邮件链路：

```text
发件人用户代理 --SMTP--> 发件邮件服务器 --SMTP--> 收件邮件服务器 <--POP3/IMAP-- 收件人用户代理
Web 邮件：浏览器与邮件系统之间使用 HTTP/HTTPS；邮件服务器之间仍使用 SMTP。
```

| 协议 | 作用 | 常见端口 |
|---|---|---:|
| SMTP | 发送邮件 | 25 |
| POP3 | 下载邮件到本地 | 110 |
| IMAP | 在线管理邮箱 | 143 |

邮件由首部和主体组成，常见首部包括 `From`、`To`、`Subject`。MIME 扩展邮件的内容类型和编码，使非 ASCII 文本、图片及附件能够通过邮件系统传输。

记忆：

```text
SMTP 负责发。
POP3/IMAP 负责收。
```

## 7. Cookie、缓存、CDN

Cookie：

```text
服务器让浏览器保存的一小段状态信息，用于识别用户或维持登录状态。
```

Web 缓存：

```text
把访问过的资源暂存起来，减少重复请求，降低服务器压力。
```

CDN：

```text
内容分发网络，把内容部署到离用户更近的节点，提高访问速度。
```

## 8. P2P 架构（Peer-to-Peer）

### 8.1 和 C/S 有什么区别

```text
C/S（客户端-服务器）：
  客户端主要从服务端获取服务，服务端是容量瓶颈之一
  （可用集群/负载均衡缓解单点压力）

P2P（对等网络）：
  每个节点既是客户端也是服务器，数据主要由对等节点直接交换
  ⚠️ P2P 不等于"没有服务器"——集中式/混合式仍有索引服务器或 Tracker；
     "节点越多越快"也不是必然（还受上传带宽、在线率、资源分布影响）
```

### 8.2 P2P 的三种实现方式

| 类型 | 怎么工作 | 例子 |
|------|---------|------|
| **集中式** | 中心索引服务器记录谁有什么，Peer之间直传 | 早期 Napster |
| **完全分布式** | 无中心，查询靠广播/邻居转发 | Gnutella |
| **混合式** | 有索引服务器，传输是P2P | Tracker 型 BitTorrent |

### 8.3 BitTorrent 怎么工作

```text
核心概念：
  .torrent 文件 → 存元信息（文件名、大小、分块长度、各块哈希；可含 Tracker 地址）
  Tracker      → 记录当前有哪些Peer在下载/上传
  Peer         → 参与下载/上传的节点
  Seed（做种） → 下载完还在上传的节点
  Piece（块）  → 文件被切成小块（大小由种子元数据指定，非固定值），可并行下载

Tracker 型典型流程：
  1. 拿到 .torrent 文件
  2. 若种群使用 Tracker，则连接 Tracker 获取其他 Peer 列表
  3. 从多个 Peer 同时请求不同块（并行下载）
  4. 下载的同时也上传已拥有的块
  5. 下载完可选择继续做种

节点发现不只依赖 Tracker；现代客户端还可使用 DHT、PEX 等方式发现 Peer。

Choking 算法（激励机制，经典客户端策略而非协议规定）：
  优先服务上传快的 Peer（投桃报李）
  周期性重新评估
  随机选一个新 Peer 乐观解除阻塞（optimistic unchoke，防止新节点被饿死）
```

### 8.4 P2P vs C/S 对比速查

| 对比项 | C/S | P2P |
|-------|-----|-----|
| 服务器 | 需要专用服务器（可用集群） | 传输主要在对等节点间；集中式/混合式仍有索引服务器 |
| 可扩展性 | 服务端是容量瓶颈 | 自扩展（节点越多总资源越丰富；受上传带宽/在线率影响） |
| 成本 | 需要部署服务器 | 成本分散 |
| 单点故障 | 服务器故障影响大（集群可缓解） | 完全分布式无中心；有索引/Tracker 时索引仍是单点 |
| 安全性 | 可控性好 | 来源可能不可信；BitTorrent 用块哈希检测传输错误或篡改，但不能替代可信发布者认证 |
| 典型应用 | Web、Email | BitTorrent、区块链 |

## 10. 考试题干识别指南

### 考应用层的常见"伪装"

考试题很少直说"应用层"，而是通过场景描述让你判断。会识别关键词就能秒破题：

| 真实考点 | 考题会怎么写（伪装） | 🎯 识别关键词 |
|---------|-------------------|-------------|
| HTTP | "用户在浏览器输入网址访问网页" | 浏览器、网页、URL |
| HTTPS | "安全地浏览网站、网上支付、登录" | 加密、安全、443 |
| DNS | "输入域名后怎么找到对应的服务器"、"域名变IP" | 域名、解析、查询 |
| FTP | "把文件上传到远程服务器"、"下载大文件" | 上传、下载、文件传输 |
| SMTP | "用户发送电子邮件"、"邮件客户端发邮件" | 发邮件、发送 |
| POP3/IMAP | "用户收取/管理邮件"、"邮件保存于本地/服务器" | 收邮件、收件箱 |
| Cookie | "网站如何记住用户的登录状态"、"购物车内容" | 保持状态、记住我 |
| CDN | "视频网站如何让全国用户都流畅观看" | 加速、就近访问、边缘节点 |
| 递归/迭代 | "DNS 查询过程中本地DNS服务器怎么工作的" | 替我去问 / 告诉我去问谁 |

### 高频考题例句（考题翻译练习）

```text
❌ 原题不会这样写："请从应用层角度分析..."
✅ 考题实际会这样写：

"用户在浏览器地址栏输入 www.example.com 并回车，
 请描述从输入到页面显示过程中涉及的网络协议。"
 → 识别：看到"浏览器"+"输入网址"+"页面显示"
 → 考点：DNS（域名解析）→ TCP（三次握手）→ HTTP（请求响应）
 → 没错，这是一道跨层综合题，但应用层的 DNS 和 HTTP 是必答部分

"Web 服务器如何识别不同的用户？"
 → 识别：看到"识别用户"
 → 考点：Cookie/Session
 → 应用层知识点：HTTP无状态 + Cookie补状态

"邮件从发送方到接收方的过程"
 → 识别：看到"邮件"
 → 考点：SMTP（发） + POP3/IMAP（收）
 → 注意：发和收是两个不同的协议，别混
```

### 一句话识别法

```
看到 "浏览器" + "网页" + "域名" + "邮件" + "上传/下载" → 应用层
看到 "握手" + "确认" + "重传" + "拥塞"                → 运输层
看到 "路由器" + "IP" + "路由表" + "子网"              → 网络层
看到 "交换机" + "帧" + "MAC" + "碰撞" + "CRC"         → 链路层
看到 "波形" + "电平" + "带宽" + "dB" + "编码"         → 物理层
```

端口号同时出现在应用层协议题和运输层复用/分用题中，必须结合协议与场景判断，不能只凭“端口”定层。
