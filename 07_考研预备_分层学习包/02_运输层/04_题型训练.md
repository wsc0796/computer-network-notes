## 1. 概念判断题

### 必背结论

```text
运输层提供进程到进程通信。
端口号用于标识主机中的应用进程。
UDP 无连接、不可靠、面向报文，首部 8 字节。
TCP 面向连接、可靠、面向字节流，首部最小 20 字节。
TCP 有流量控制和拥塞控制，UDP 没有。
TCP 面向字节流，UDP 面向报文，不能背反。
```

### 常见陷阱

| 题干 | 判断 | 原因 |
|---|---|---|
| TCP 是面向报文的 | 错 | TCP 面向字节流 |
| UDP 提供可靠交付 | 错 | UDP 尽最大努力交付 |
| 端口号只在本地主机有意义 | 对 | 端口用于本机进程标识 |
| UDP 首部最小 20 字节 | 错 | UDP 首部固定 8 字节 |
| TCP 首部固定 20 字节 | 错 | TCP 首部最小 20 字节，有选项会变长 |

### 学习通真题（老师作业，7题）

| 题号 | 题干 | 正确答案 | 陷阱/易混点 |
|---:|---|---|---|
| 1 | 应用层进程通过什么与运输层实体交互？ | **端口** | 不是IP地址、不是Socket（Socket是编程接口，端口是协议概念） |
| 2 | 端口号的长度是多少位？ | **16位**（0~65535） | UDP源端口/目的端口各2字节=16位，要能换算 |
| 3 | 运输层不可靠传输协议是什么？ | **UDP** | UDP不保证可靠交付，但可由应用层自己实现可靠机制 |
| 4 | TCP和UDP哪个通常效率更高？为什么？ | **UDP**，无连接、首部小（8字节）、无流控和拥塞控制 | 效率高≠可靠，UDP牺牲可靠性换效率 |
| 6 | 以下哪项不是UDP的特性？ | **提供可靠服务** | UDP的特性：无连接、尽最大努力、面向报文、首部8字节、支持校验和 |
| 7 | "TCP是面向报文的，UDP是面向字节流的"对吗？ | **错** | TCP面向字节流（不保留报文边界），UDP面向报文（保留报文边界） |
| 8 | "网络层提供数据报或虚电路服务不影响运输层的运行机制，但影响服务质量"对吗？ | ◐ 有条件的对（特定课程判断题） | 一般语境下成立：运输层机制（TCP/UDP）不因下层是数据报还是虚电路而重写；但下层服务的可靠性/顺序/连接语义会影响运输层需要采用的机制，且服务质量（丢包、时延、吞吐率）确实受网络层影响——完整判断题需保留题干限定 |

## 2. UDP/TCP 首部字段题

### UDP 首部

UDP 首部固定 8 字节：

| 字段 | 长度 | 作用 |
|---|---:|---|
| 源端口 | 2 字节 | 发送方应用进程端口 |
| 目的端口 | 2 字节 | 接收方应用进程端口 |
| 长度 | 2 字节 | UDP 首部 + 数据 |
| 校验和 | 2 字节 | 检错 |

### TCP 首部关键字段

| 字段 | 作用 |
|---|---|
| 源端口/目的端口 | 标识通信进程 |
| seq | 本报文段数据第一个字节编号 |
| ack | 期望收到的下一个字节编号 |
| 数据偏移 | 指出 TCP 数据从哪里开始 |
| 窗口 | 接收窗口，用于流量控制 |
| SYN | 建立连接 |
| ACK | 确认号有效 |
| FIN | 释放连接 |
| RST | 复位连接 |

### seq/ack 计算模板

题目给：

```text
seq = a
数据长度 = L
```

则下一个序号：

```text
next seq = a + L
```

如果接收方成功收到这些字节，确认号：

```text
ack = a + L
```

注意：

```text
SYN 和 FIN 虽然不携带普通数据，但各消耗 1 个序号。
纯 ACK 不消耗序号。
```

## 3. RDT 与停止等待题

### RDT 递进

| 协议 | 信道问题 | 新增机制 |
|---|---|---|
| RDT 1.0 | 信道完全可靠 | 无需额外机制 |
| RDT 2.0 | 分组可能出错 | ACK/NAK |
| RDT 2.1 | ACK/NAK 也可能出错 | 序号 |
| RDT 2.2 | 不使用 NAK | 重复 ACK 表达未收到 |
| RDT 3.0 | 分组可能丢失 | 定时器、超时重传 |

### 停止等待时序

必须能画四种情况：

```text
1. 正常：发送 M1 -> ACK -> 发送 M2
2. 数据丢失：M1 丢失 -> 超时 -> 重传 M1
3. ACK 丢失：B 收到 M1 -> ACK 丢失 -> A 超时重传 -> B 丢弃重复 M1
4. ACK 迟到：A 先超时重传，后收到迟到 ACK，需要靠序号避免混乱
```

### 信道利用率

常见思想：

```text
停止等待信道利用率低，因为发送一个分组后必须等待 ACK，RTT 越大，等待浪费越明显。
```

若题目给公式型数据，先找：

```text
发送时延
RTT
确认帧发送时延是否忽略
```

常见简化：

```text
利用率 = 发送时延 / (发送时延 + RTT)
```

## 4. GBN 与 SR 题

### GBN

关键词：

```text
Go-Back-N
接收窗口通常为 1
只按序接收
乱序帧丢弃
累计确认
最早未确认帧超时后，重传该帧及其后所有已发送但未确认的帧（发送方未必知道哪帧丢失）
```

### SR

关键词：

```text
Selective Repeat
接收方可以缓存乱序帧
逐个确认
只重传丢失帧
接收方缓存和逻辑更复杂
```

### 最大窗口

若序号位数为 n：

```text
GBN 最大发送窗口 <= 2^n - 1
SR 最大窗口 <= 2^(n-1)
```

原因：

```text
窗口过大时，新旧帧序号会混淆，接收方无法判断是新一轮数据还是旧数据重传。
```

### 对比表

| 对比 | GBN | SR |
|---|---|---|
| 接收乱序帧 | 丢弃 | 缓存 |
| 确认方式 | 累计确认 | 逐个确认 |
| 重传方式 | 从丢失处开始全部重传 | 只重传丢失帧 |
| 接收窗口 | 通常为 1 | 大于 1 |
| 实现复杂度 | 较低 | 较高 |

## 5. TCP 可靠传输题

### 必会机制

```text
以字节为单位编号
累计确认
超时重传
快重传
RTT/RTO 估计
Karn 算法
SACK 选择确认
```

### ACK 规则

```text
ACK = x 表示 x 之前的字节都已经收到，下一步期望收到 x。
```

例：

```text
ACK = 1001
表示 1-1000 都收到了，下一步要 1001。
```

### Karn 算法

```text
重传过的报文段，其 ACK 不用于更新 RTT。
因为无法判断 ACK 对应原始报文段还是重传报文段。
```

修正规则：

```text
每次超时重传，RTO 加倍。
```

### SACK

```text
SACK 通过 TCP 选项告诉发送方哪些乱序数据块已经收到。
作用是只重传缺失数据，减少不必要重传。
```

## 6. RTT/RTO 计算题

### 公式

```text
新的 RTTs = (1 - alpha) * 旧 RTTs + alpha * 新 RTT 样本
alpha = 1/8
```

```text
新的 RTTd = (1 - beta) * 旧 RTTd + beta * |RTTs - 新 RTT 样本|
beta = 1/4
```

```text
RTO = RTTs + 4 * RTTd
```

### 做题步骤

```text
1. 看题目给的是旧 RTTs、旧 RTTd 还是只给 RTT 样本。
2. 先算新的 RTTs。
3. 再算新的 RTTd。
4. 最后算 RTO。
5. 如果报文段被重传过，注意 Karn 算法，不用该 ACK 更新 RTT。
```

## 8. 拥塞控制题

### 必背公式

```text
发送窗口 = min(rwnd, cwnd)
```

```text
rate = cwnd / RTT
```

### 慢开始与拥塞避免

| 阶段 | 增长方式 |
|---|---|
| 慢开始 | 指数增长 |
| 拥塞避免 | 线性增长 |

规则：

```text
cwnd < ssthresh：慢开始
cwnd > ssthresh：拥塞避免
cwnd = ssthresh：两者均可
```

### 拥塞事件处理

超时：

```text
ssthresh = cwnd / 2
cwnd = 1 MSS
重新慢开始
```

3 个重复 ACK：

```text
快重传 + 快恢复
ssthresh = cwnd / 2
cwnd = ssthresh
进入拥塞避免
```

### cwnd 曲线判断

看到曲线：

```text
cwnd 突然降到 1：通常是超时。
cwnd 降到约一半：通常是 3 个重复 ACK / 快恢复。
```

## 9. TCP 连接管理题

### 三次握手

```text
1. 客户端 -> 服务器：SYN=1, seq=x
2. 服务器 -> 客户端：SYN=1, ACK=1, seq=y, ack=x+1
3. 客户端 -> 服务器：ACK=1, seq=x+1, ack=y+1
```

作用：

```text
确认双方收发能力
交换初始序号
防止已失效连接请求突然到达服务器造成错误连接
```

### 四次挥手

```text
1. 主动关闭方 -> 被动关闭方：FIN
2. 被动关闭方 -> 主动关闭方：ACK
3. 被动关闭方 -> 主动关闭方：FIN
4. 主动关闭方 -> 被动关闭方：ACK
```

为什么四次：

```text
TCP 是全双工通信，一方不发送数据，不代表另一方也不发送。
两个方向需要分别关闭。
```

### TIME-WAIT

```text
主动关闭方发送最后 ACK 后进入 TIME-WAIT，等待 2MSL。
```

作用：

```text
保证最后 ACK 能到达。
让旧连接报文段从网络中消失，避免干扰新连接。
```

## 10. 简答题模板库

### TCP 如何保证可靠传输

```text
TCP 在不可靠的 IP 层之上，通过序号、确认、重传和滑动窗口实现可靠传输。
序号用于标识字节顺序，确认用于告知发送方哪些数据已正确收到。
当报文段丢失或确认超时时，TCP 进行超时重传；收到多个重复 ACK 时可进行快重传。
TCP 还使用校验和检测差错，并通过累计确认、SACK 等机制提高重传效率。
```

### 流量控制和拥塞控制区别

```text
流量控制用于防止发送方发送太快，使接收方来不及接收，主要依据接收方通告窗口 rwnd。
拥塞控制用于防止过多数据注入网络导致网络过载，主要依据拥塞窗口 cwnd、丢包和 RTT 等网络状态。
实际发送窗口通常取 min(rwnd, cwnd)。
```

### 为什么三次握手不是两次

```text
三次握手用于确认双方的发送和接收能力，并交换初始序号。
如果只有两次握手，已经失效的旧连接请求报文段可能延迟到达服务器，使服务器误以为客户端要建立新连接，造成资源浪费。
第三次握手可以让服务器确认客户端收到了自己的确认和初始序号，从而可靠建立连接。
```

### 为什么四次挥手通常是四次

```text
TCP 是全双工通信，两个方向的数据传输需要分别关闭。
一方发送 FIN 只表示自己没有数据要发送了，但对方可能还有数据要继续发送。
因此对方先返回 ACK，等自己的数据发送完后再发送 FIN，最后由主动关闭方返回 ACK。
```

## 14. 408 真题专章（半幺郎 分章节真题，2009-2025）

> 来源：`08_网盘资料接入/extracted_true_questions/05-运输层真题OCR.md`
> 定位：运输层是 408 选择题+大题双核心，**考点非常集中**——只有 UDP 和 TCP 两个协议，TCP 是重中之重。
> 掌握标准：以下每题闭卷能做对。

### 14.1 考点一：UDP

**2014 真题（单选）**：下列关于 UDP 协议的叙述中，正确的是？

> ① 提供无连接服务 ② 提供复用/分用服务 ③ 通过差错校验，保障可靠数据传输
> 答案：**①② 对，③ 错**（UDP 校验和只检错、不保证可靠交付）。
> 记忆：UDP = 无连接 + 尽最大努力交付 + 校验和（可选用）。

**2018 真题（单选）**：UDP 协议实现分用（demultiplexing）时所依据的头部字段是？

> 答案：**目的端口号**。分用 = 根据目的端口把数据报交给对应进程。
> 对比：复用 = 多个进程用不同源端口发数据。

**2024 真题（单选，校验和计算）**：若 UDP 在计算校验和过程中，计算到中间结果为 1011 1001 1011 0110 时，还需要加上最后一个 16 位数 0110 0101 1100 0101，则最终计算得到的校验和是？

> 答案：**1110 0000 1000 0011（0xE083）**。
> 计算：0xB9B6 + 0x65C5 = 0x11F7B → 回卷（最高位进位加到最低位）= 0x1F7C → 取反 = 0xE083。
> 考点：UDP 校验和 = 伪首部 + UDP 首部 + 数据 的 16 位字反码求和取反（回卷 + 取反两步）。

**2025 真题（单选，NAT 结合）**：内网主机 H 通过 NAT 路由器向 Internet 发送 UDP 报文段，路由器在转发封装该 UDP 报文段的 IP 数据报过程中，UDP 报文首部字段可能会被修改的是？

> 答案：**源端口号**——对应 **NAPT**（改源 IP + 源端口，用端口区分不同内网主机）；普通 **NAT 只改源 IP**，不改端口。
> 题目问"改写哪个字段来区分主机" → NAPT 的**源端口**；⚠️ 校验和会因 IP/端口被改写而**连带重算**（校验和也是 UDP 首部字段），但那是伴随效应，不是本题答案；IPv4 UDP 校验和为 0（未启用）时无需重算。

### 14.2 考点二：TCP 段与效率

**2021 真题（单选）**：大小为 12B 的应用层数据分别通过一个 UDP 数据报和一个 TCP 段传输，则该 UDP 数据报和 TCP 段实现的应用层数据最大传输效率分别是？

> 答案（两种口径，先确定分母再算）：
> - 只计运输层首部：UDP 12/(12+8) = **60%**；TCP 12/(12+20) = **37.5%**
> - 计入 IPv4 首部 20B：UDP 12/(12+8+20) = **30%**；TCP 12/(12+20+20) ≈ **23.1%**
> ⚠️ 伪首部**不参与传输，不计入效率分母**——不存在"含伪首部"口径；
> 分母只能是实际传输的字节（运输层首部，或+IP 首部），按题目对"效率"的定义选择。
> 解题要点：**先确定分母包含哪些首部**（运输层首部？IP 首部？），再算；不要在同一题里混用口径。
> 核心记忆：UDP 首部 8B、TCP 首部 20B、IP 首部 20B；效率 = 应用数据 / 总字节数。

### 14.3 考点三：TCP 连接管理（三握四挥）

**2011 真题（单选）**：主机甲向主机乙发送一个（SYN=1, seq=11220）的 TCP 段，期望建立连接。若主机乙接受该连接请求，则主机乙向主机甲发送的正确的 TCP 段可能是？

> 答案：**（SYN=1, ACK=1, seq=11221, ack=11221）**。
> 考点：第二次握手 = SYN+ACK 都置 1，seq 是乙自选的初始序号，ack = 甲的 seq+1。

**2019 真题（单选）**：若主机甲主动发起一个与主机乙的 TCP 连接，甲、乙选择的初始序列号分别为 2018 和 2046，则第三次握手 TCP 段的确认序列号是？

> 答案：**2047**（确认号 = 乙的初始序号 2046 + 1）。
> 记忆：三次握手的 ack：第一次无 ack；第二次 ack=甲序+1；第三次 ack=乙序+1。

**2021 真题（单选，状态转换）**：若客户首先向服务器发送 FIN 段请求断开 TCP 连接，则当客户收到服务器发送的 FIN 段并向服务器发送了 ACK 段后，客户的 TCP 状态转换为？

> 答案：**TIME_WAIT**。
> 流程：客户发 FIN → FIN_WAIT_1 → 收到 ACK → FIN_WAIT_2 → 收到服务器 FIN → 发 ACK → **TIME_WAIT（等 2MSL）**。

**2020 真题（单选）**：若主机甲与主机乙建立 TCP 连接时，发送的 SYN 段中的序号为 100，在断开连接时发送给乙的 FIN 段中的序号为 5001，则在无任何重传的情况下，甲向乙已经发送的应用层数据的字节数为？

> 答案：**4900**（5001 - 100 - 1 = 4900，SYN 占 1 个序号）。
> 陷阱：SYN 和 FIN 各占 1 个序号——如果 FIN 序号包含 SYN 占位，数据字节数 = FIN序号 - SYN序号 - 1。

**2022 真题（单选）**：假设客户 C 和服务器 S 已建立一个 TCP 连接，RTT=50ms，MSL=800ms，数据传输结束后 C 主动断开。若从 C 主动向 S 发出 FIN 段时刻算起，则 C 和 S 进入 CLOSED 状态所需的时间至少分别是？

> 答案：**C 至少 1650ms；S 至少约 75ms**（按单向时延 = RTT/2 = 25ms 的通常模型）。
> 计算：
> - C 发 FIN（t=0）→ 25ms 后 S 收到 → S 回 ACK + 发 FIN（C 约 50ms 收齐）→ C 发最后 ACK（t=50ms）→ TIME_WAIT 2MSL = 1600ms → C 于 **t = 50 + 1600 = 1650ms** 进入 CLOSED；
> - S：收到 C 的 FIN 后回 ACK 并发 FIN（约 25ms），C 的 ACK 约 25ms 后到达（t≈50ms）；S 无需等 2MSL，约 **75ms** 内可进入 CLOSED。
> 考点：客户端 TIME_WAIT 必须等 2MSL；2MSL 的起算点是**发送最后一个 ACK 之后**，不是收到 FIN 时。

**2025 真题（单选）**：某客户与 Time 服务器往返时间为 8ms，则该客户分别通过 UDP 和 TCP 向该服务器请求服务，到客户收到时间信息为止所需的最短时间分别是？

> 答案：**UDP：8ms（1 个 RTT）；TCP：16ms（三次握手约 1 RTT + 请求响应 1 RTT）**。
> 考点：TCP 有连接建立开销，UDP 无连接直接发。

### 14.4 考点四：TCP 可靠传输（seq/ack 计算，408 必考）

**2009 真题（单选）**：主机甲向主机乙发送两个连续的 TCP 段，分别包含 300B 和 500B 的有效载荷，第一个段的序号为 200。主机乙正确接收到两个段后，发送给主机甲的确认序列号是？

> 答案：**1000**（200 + 300 + 500 = 1000）。
> 累计确认：确认号 = 期望收到的下一个字节序号。

**2011 真题（单选）**：主机甲向主机乙发送 3 个连续的 TCP 段，分别包含 300B、400B 和 500B 的有效载荷，第三个段的序号为 900。若主机乙仅正确接收到第一个和第三个段，则主机乙发送给主机甲的确认序号是？

> 答案：**500**（第一段 300B 已收，期望下一个字节是 200+300=500；第三段虽收到但序号不连续，累计确认只确认到 500）。
> 陷阱：乱序收到的段不改变累计确认号——TCP 只确认连续收到的部分。

**2013 真题（单选）**：主机甲与主机乙之间已建立 TCP 连接，双方持续有数据传输且无差错。若甲收到一个来自乙的 TCP 段，该段的序号为 1913，确认序号为 2046，有效载荷为 100 字节，则甲立即发送给乙的 TCP 段的序号和确认序号分别是？

> 答案：**序号 2046，确认号 2013**。
> 甲发的序号 = 收到的确认号（2046）；甲发的确认号 = 收到的序号 + 载荷（1913+100=2013）。

### 14.5 考点五：TCP 流量控制

**2021 真题（单选）**：主机甲在 t1 时刻发送一个序号为 501、封装 200B 数据的段，在 t2 时刻收到乙发送的序号 seq=601、确认序号 ack=501、接收窗口 rwnd=500 的段，则甲在未收到新的确认段之前，可以继续向乙发送的数据序号范围是？

> 思路（正确推导）：
> - 乙确认到 ack=501，说明 **501 及以后尚未确认**；甲已发未确认 = 501~700 共 200B
> - 发送窗口 = min(cwnd, rwnd) = 500（题设 cwnd 不构成限制）
> - 还能发送 = 500 - 200（已发未确认）= 300B → **新数据 701~1000**
> 答案：**701~1000 共 300B**（已发未确认 200B 从窗口 500B 中扣除，新数据 = 501 起跳过已发部分，即 701~1000）。
> 核心：**先算已发未确认，再从窗口里扣**，不能把 701 之后的整个窗口都当新数据。

**2025 真题（单选）**：主机甲通过 TCP 连接向主机乙传输数据，seq 为序号，ack_seq 为确认号，rcwnd 为接收窗口大小。假设在 t1 时刻甲的拥塞窗口为 8 MSS、发送窗口为 2 MSS（MSS=1000B，题设数字需以原题图为准），甲始终以最大段长发 TCP 段，若甲在 t1 时刻收到确认及通告窗口，则在收到新的确认段之前还可以再向乙发送多少个 1000B 的段？

> 思路：发送窗口 = min(cwnd, rwnd)；已发未确认的段数从窗口里扣除后，剩余可发段数 = 发送窗口 - 已发未确认段数。
> 考点：窗口计算的综合应用（2025 最新真题，强化重点；⚠️ 原题有窗口状态图，图中 t1 时刻的已发未确认段数决定答案——OCR 缺图，刷题时对照原卷图作答）。

### 14.6 考点六：TCP 拥塞控制（408 高频考查）

**2009 真题（单选）**：TCP 连接总是以 1KB 的最大段长发送 TCP 段，发送方有足够多的数据要发送。当拥塞窗口为 16KB 时发生了超时，如果接下来的 1 个 RTT 时间内 TCP 段的传输都是成功的，那么当第 1 个 RTT 时间内发送的所有 TCP 段都得到肯定应答时，拥塞窗口大小是？

> 答案：**2KB**。
> 计算：超时后 cwnd=1KB、ssthresh=8KB（16/2）；"接下来的 1 个 RTT"内慢开始只翻倍一次：1 → **2KB**。
> ⚠️ 9KB 是"多个 RTT 连续成功"（1→2→4→8→9，共 4 轮）的错误回忆答案——题干明确"1 个 RTT"时唯一答案是 2KB，不要混用口径。

**2014 真题（单选）**：甲始终以 MSS=1KB 发送数据，乙每收到一个数据段都会发出一个接收窗口为 10KB 的确认段。若甲在 t1 时刻发生超时时拥塞窗口为 8KB，则从 t1 时刻起，不再发生超时的情况下，经过 10 个 RTT 后甲的发送窗口是？

> 答案：**10KB**（min(cwnd, rwnd)，rwnd 是瓶颈）。
> 超时后：cwnd=1，ssthresh=4；慢开始 1→2→4→5→…，但发送窗口 = min(cwnd, 10KB)，cwnd 超过 10KB 后被 rwnd 卡住 → 10KB。

**2015 真题（单选）**：甲的拥塞控制初始阈值为 32KB，乙分配 16KB 接收缓存且数据不被取走，从连接建立成功时刻起未发送超时，经过 4 个 RTT 后甲的发送窗口是？

> 答案：**1KB**。
> 计算：慢开始 4 个 RTT 累计接收 = 1+2+4+8 = **15KB**（缓存 16KB 且数据不被取走 → rwnd 递减为 16-15 = **1KB**）；此时发送窗口 = min(cwnd=16KB, rwnd=1KB) = **1KB**。
> 陷阱：**rwnd 随接收缓存占用而递减**，不是固定值；数据不被取走时最终会通告 0 窗口。

**2010 真题（单选）**：TCP 最大段长度为 1000B，甲的当前拥塞窗口为 4000B，连续发送两个最大段后成功收到乙发送的第一个段的确认段，确认段中通告的接收窗口大小为 2000B，此时甲还可以向乙发送的最大字节数是？

> 答案：**1000B**。
> 计算：发送窗口 = min(4000, 2000) = 2000；已发未确认 1000B（第二个段）→ 2000-1000 = 1000。

**2017 真题（单选）**：MSS=1KB，RTT=5ms，乙开辟接收缓存 64KB，则甲从连接建立成功起发送窗口达到 32KB 需经过的时间至少是？

> 答案：**25ms**（按题干"从连接建立成功起"：慢开始 1→2→4→8→16→32 需 5 个 RTT = 25ms）。
> ⚠️ 若答案 30ms，则原题计时起点是"从开始建连"（含建连 1 RTT）——**按题干口径作答**，两者差一个建连 RTT；ssthresh 若低于 32KB 则还需线性增长更久。

**2020 真题（单选）**：MSS=1KB，RTT=2ms，不出现拥塞的前提下，拥塞窗口从 8KB 增长到 32KB 所需的最长时间是？

> 答案：**48ms**（最长时间 = 全程拥塞避免：8→32 需 24 个 RTT × 2ms）。
> 关键公式：慢开始每 RTT 翻倍（最快），拥塞避免每 RTT +1（最慢）——问"最长时间"就按全程线性增长算；ssthresh 若已知则分两段计算。

**2022 真题（单选）**：MSS=1KB，当甲的拥塞窗口为 16KB 时计时器发生超时，则甲的拥塞窗口再次增长到 16KB 所需要的时间至少是？

> 答案：**11 RTT**。
> 超时：cwnd=1，ssthresh=8；慢开始 1→2→4→8（3 个 RTT），线性 9→…→16（8 个 RTT），共 11 RTT。
> 关键：**超时后 ssthresh=cwnd/2，cwnd=1，慢开始到 ssthresh 后线性增长**。

**2024 真题（单选）**：主机 H 通过 TCP 向服务器发送长度为 3000B 的报文，RTT=10ms，MSL=30ms，MSS=1000B，忽略传输时延。报文传输结束后 H 首先请求断开连接，则从 H 请求建立 TCP 连接时刻起，到 H 进入 CLOSED 状态为止所需的时间至少是？

> 答案：按阶段公式加总（原题未给出初始 cwnd、确认策略、第三次握手是否携带数据等计时条件，无法得到唯一数值——做题时按下面套路分阶段加总，对照原题选项选择）。
> 阶段（RTT=10ms、MSL=30ms、MSS=1000B、3000B 分 3 段）：
> 建连 1 RTT（10ms）+ 传输（约 1~2 RTT）+ 挥手（主动断开约 1~1.5 RTT）+ TIME_WAIT 2MSL（60ms）
> 总时间必然 > 60ms（2MSL 下限）。
> 综合题套路：总时间 = 建连 + 传输 + 挥手 + TIME_WAIT(2MSL)，分阶段加总，不要漏阶段或让总时间小于 2MSL。

### 14.7 考点七：综合大题（跨章节）

**2016 真题（综合大题）**：H3 访问 Web 服务器 S 时，为新建 TCP 连接分配 20KB（R=1024）接收缓存，MSS=1KB，RTT=200ms，初始序号 100，拥塞窗口初始阈值 32KB，S 对收到的每个段进行确认并通告新接收窗口。假定接收缓存只有数据存入而无数据取出。问：
> (1) 三次握手中 H3 收到的第二次握手 TCP 段的 SYN 和 ACK 标志位值？确认号？（SYN=1, ACK=1, ack=101）
> (2) 第一个确认段通告的接收窗口？（20KB）；此时拥塞窗口？（慢开始 1KB）；发送窗口 = min(cwnd, rwnd) = 1KB
> (3) 发送窗口等于 0 时下一个待发数据段序号？平均数据传输速率？
>     计算：慢开始 cwnd 每 RTT 翻倍（1→2→4→8→16），累计接收 1+2+4+8=15KB 后 rwnd=5KB；
>     第 5 个 RTT 发送窗口 = min(16, 5) = 5KB → 再发 5 段 → 累计 20KB = 20×1024 = 20480B → rwnd=0 → 发送窗口为 0。
>     序号：SYN 占用初始序号 100，数据从 **101** 开始编号；已发 20480B → 下一个待发段序号 = 101 + 20480 = **20581**；
>     平均速率 = 20480B × 8 / 5 RTT（1000ms）≈ **164kbps**（20480×8 = 163840 bit / 1s；数值以原题图为准）。
> (4) 断开连接最短时间：原题文字条件缺 MSL，(4) 无法独立数值化——需按原卷给定的 MSL 套「挥手 + 2MSL」计算。
> 考点：**接收缓存不取出 → rwnd 持续减小 → 发送窗口最终为 0**，全流程串联。

**2023 真题（综合大题 9 分，FTP+TCP）**：主机 H 登录 FTP 服务器后上传一个 1GB 文件 F。H 为建立数据连接选择的初始序号、拥塞控制初始阈值 8MSS，RTT=...（原题给定具体数值，OCR 缺失），传输过程中平均以 MSS 段为单位发送数据且未发生差错和乱序。问：
> (1) FTP 控制连接持久/非持久？数据连接？（控制**持久**、数据**非持久**——可独立作答）
> (2) F 的第一个字节序号是多少？（**初始序号+1**——可独立作答）
> (3) 断开数据连接时 FTP 服务器及 H 的第二次挥手 ACK 段的确认序号？（需用初始序号与已传字节数计算，原题数值缺失时按「确认号 = 收到的 FIN 序号 + 1」规则作答）
> (4) 收到确认号 2101 的确认时拥塞窗口调整为多少？收到 7101 的确认时？（按 MSS=1000B：2101 对应约第 2~3 段确认，7101 对应第 7 段——套慢开始/拥塞避免递推）
> (5) 从请求建立数据连接开始到服务器全部接收为止至少需要多长时间？应用层数据平均发送速率？（需 RTT 数值，OCR 缺失——对照原卷补数值后按「建连 + 传输 + 挥手」加总）
> ⚠️ RTT 等数值在 OCR 转录中缺失，(3)(5) 无法数值化；(1)(2) 与 (4) 的递推规则可独立训练。
> 考点：**FTP 数据连接 + TCP 拥塞控制 + 时延计算三合一**（2023 最新综合大题）。
