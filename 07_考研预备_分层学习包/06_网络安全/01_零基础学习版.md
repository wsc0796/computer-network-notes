## 1. 网络安全解决什么问题

网络通信面临四大威胁：

```text
截获（窃听）   → 破坏机密性
篡改           → 破坏完整性
伪造           → 破坏真实性（认证问题）
中断（DoS）    → 破坏可用性

安全目标：
  机密性（Confidentiality）：数据不被未授权者读取
  完整性（Integrity）：数据不被篡改
  认证/真实性（Authentication）：确认对方身份
  不可否认性（Non-repudiation）：发送方不能否认发过
  可用性（Availability）：服务在需要时可被使用（如 DoS 攻击破坏的就是可用性）
```

一句话主线：

```text
机密性靠"加密"，完整性靠"报文鉴别码/签名"，
身份认证靠"数字签名 / 挑战-响应（依赖可信公钥绑定）"，五目标组合成完整安全体系。
```

## 2. 对称加密 vs 非对称加密（最核心考点）

### 对称加密

```text
加密和解密用同一个密钥（共享密钥）
代表：DES、3DES、AES（现代标准）

优点：加密快，适合大数据量
缺点：密钥分发困难——双方怎么安全地拿到同一个密钥？
      密钥管理困难——N 个人两两通信需要 N(N-1)/2 个不同的共享密钥
```

### 非对称加密（公钥密码）

```text
一对密钥：公钥（公开）+ 私钥（保密）
公钥加密 → 私钥解密（用于机密性）
数字签名：私钥执行签名算法 → 公钥验证（用于认证/签名；
  RSA 教学简化说"私钥加密摘要"，但 DSA/ECDSA 是独立签名算法，不存在"私钥加密、公钥解密"）

代表：RSA

优点：密钥分发简单（公钥可公开——但必须经可信渠道认证绑定持有者身份，否则攻击者替换公钥即可实施中间人攻击）
缺点：加密慢，不适合大数据量
```

### 核心考点：两者怎么配合

```text
实际网络通信 = 非对称加密"传/协商密钥材料" + 对称加密"传数据"

流程：
  1. 用非对称算法安全地传输或协商出密钥材料（旧式 RSA 传输预主密钥；
     DHE/ECDHE 才是双方协商共享秘密；会话密钥每次通信临时生成）
  2. 后续大数据量通信用 AES 等对称算法加密
  3. 这样既有非对称的安全密钥分发，又有对称的高效加密
```

> 这就是 HTTPS 的核心思路（教材第 7 章经典考点；408 大纲无独立安全章，
> 该知识以应用层散点形式出现，不能断言"最爱考"）。

## 3. 报文鉴别 vs 数字签名（最容易混淆的一对）

### 报文摘要（完整性检验）

```text
解决：消息是否被篡改？（检测传输差错）
方法：报文摘要（散列函数）
  MD5（128 位）、SHA-1（160 位）、SHA-256

关键点：
  散列函数是单向的（不可逆）
  碰撞必然存在（摘要空间有限），安全散列应使**寻找碰撞在计算上不可行**
  （MD5、SHA-1 的抗碰撞性已失效，现代使用 SHA-256 等）
  报文 + 摘要一起发送，接收方重新计算比对

⚠️ 裸摘要**只能检出传输差错**：主动攻击者可同时修改报文并重算摘要。
  "报文鉴别"（确认发送方身份）必须由 MAC（共享密钥）或数字签名（私钥）实现。
```

### 报文鉴别码（MAC，Message Authentication Code）

```text
发送方用共享密钥对报文生成鉴别码，接收方用同一密钥验证
解决：完整性 + 确认发送方（因为只有双方有密钥）
用散列函数实现的就是 HMAC（不是简单拼接散列）
```

### 数字签名（认证 + 不可否认性）

```text
本质：发送方用私钥对报文摘要执行签名算法 = 签名
  （RSA 教学简化说"私钥加密摘要"，但 DSA/ECDSA 不是加密——统一说"私钥签名"）
  发送方：对报文摘要执行私钥签名 → 数字签名
  接收方：用发送方公钥验证签名 → 一致 = 未篡改 + 来自私钥持有者

数字签名能解决：
  1. 认证：只有持有私钥的人才能生成这个签名（前提：公钥与身份已可信绑定）
  2. 完整性：验证失败说明被篡改
  3. 不可否认性：签名只能用私钥生成，无法抵赖

对比记忆：
  报文鉴别码（MAC）：确认"没被篡改 + 来自共享密钥方"
  数字签名：确认"没被篡改 + 来自私钥持有者 + 无法抵赖"
  报文鉴别码比数字签名少一个"不可否认性"
```

### 对比表

| 特性 | 报文摘要（裸摘要） | 报文鉴别码（MAC） | 数字签名 |
|------|:---:|:---:|:---:|
| 防篡改（完整性） | ⚠️ 仅能检出传输差错 | ✅ | ✅ |
| 认证发送方 | ❌ | ✅（共享密钥） | ✅（私钥） |
| 不可否认 | ❌ | ❌ | ✅ |
| 需要什么 | 散列函数 | 使用共享密钥生成鉴别码（散列实现即 HMAC） | 私钥签名 + 公钥验证 |

> ⚠️ 裸摘要**不能**抵抗主动篡改：攻击者可同时改报文并重算摘要。
> 报文鉴别（认证发送方）必须用 MAC（共享密钥）或数字签名（私钥）实现。
> 所以对比表里"报文摘要防篡改"只能算 ⚠️，不是 ✅。

## 4. HTTPS 的安全流程（旧式 TLS_RSA 简化版，⚠️ 非完整握手）

```text
HTTPS = HTTP + TLS/SSL（端口 443）

TLS 握手流程（旧式 TLS_RSA 密钥传输简化示例，仅限教学主线）：
  ① 客户端发：支持的加密套件列表 + 客户端随机数
  ② 服务器返回：数字证书 + 选定加密套件 + 服务器随机数
  ③ 客户端验证证书（CA 签名、有效期、主机名等）→ 生成预主密钥
     → 用服务器公钥加密预主密钥（RSA 密钥传输）→ 发给服务器
  ④ 双方用"客户端随机数 + 服务器随机数 + 预主密钥"
     → 经 KDF 派生会话密钥（对称密钥）
  ⑤ 之后通信用会话密钥对称加密（TLS 还提供完整性/认证保护；
     完整握手还有 Finished 等消息校验握手记录——这里只列密钥建立主线）

⚠️ 版本说明：③ 是旧式 TLS_RSA 密钥传输，不是双方"协商"会话密钥（RSA 传输是
  客户端生成、服务器解密）。TLS 1.2 还可用 DHE/ECDHE（前向保密）；
  TLS 1.3 已取消 RSA 密钥传输，改用（EC）DHE 密钥协商——408 若考现代 TLS，
  不要按 RSA 传输作答。

关键点：
  证书 = 服务器身份 + 服务器公钥 + CA 数字签名
  CA（证书颁发机构）解决"公钥是不是真的"问题（信任链验证）
  证书里 CA 的签名 = CA 私钥执行签名算法（数字签名的应用）
```

> 考点提炼：HTTPS 用到**非对称密码（密钥传输/证书签名/身份认证）** + **对称加密（会话密钥）** + **数字签名（CA 签名证书）**——一个流程串起整个网络安全。

## 5. 防火墙（概念级）

```text
防火墙 = 网络边界的安全设备，按规则过滤进出网络的数据包

分类：
  1. 网络层防火墙（包过滤）：检查 IP 首部和传输层端口
     → 如"只允许 80/443 端口进入"
  2. 应用层防火墙（代理）：检查应用层内容
     → 如"禁止下载 .exe 文件"

局限（传统边界防火墙**不能完全防御**，以下均强调"不能完全"，而非"完全不能"）：
  不能完全防病毒（病毒在数据里，但应用层/下一代防火墙可识别部分恶意内容）
  不能完全防内部攻击（内部人员可绕过防火墙，但内部隔离防火墙可缓解）
  不能完全防 DoS（大规模 DDoS 很难靠单一设备过滤，防火墙/限流/ACL 只能缓解一部分）
```

## 6. 常见攻击方式（选择题常考）

| 攻击 | 原理 | 防御 |
|------|------|------|
| 窃听（嗅探） | 截获通信内容 | 加密 |
| 篡改 | 修改传输中的报文 | 报文鉴别/签名 |
| 重放攻击 | 重新发送捕获的合法报文 | 序号/时间戳 + 鉴别 |
| 中间人攻击 | 冒充双方分别通信 | CA 证书验证 |
| DoS 拒绝服务 | 洪泛请求耗尽资源 | 防火墙/限流 |
| 钓鱼 | 伪装可信方骗取信息 | 用户教育/证书验证 |
