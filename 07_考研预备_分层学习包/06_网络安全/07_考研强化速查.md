## 一、安全目标

```text
机密性 → 加密
完整性 → 报文鉴别（MAC/签名；裸摘要只能检出传输差错）
认证   → 数字签名 / 基于公钥的挑战-响应（依赖可信公钥绑定）；口令等也可认证
不可否认 → 数字签名
可用性 → 被 DoS 攻击破坏
```

## 二、加密体系（最核心）

### 对称加密

```text
同密钥加解密：DES → 3DES → AES（现代标准）
优点：快
缺点：密钥分发难、密钥管理 O(N²)
```

### 非对称加密

```text
公钥/私钥对：RSA
公钥加密 → 私钥解密（机密性）
私钥执行签名算法 → 公钥验证（签名/认证；RSA 教学简化说"私钥加密摘要"）
优点：密钥分发简单
缺点：慢
```

### 混合体系（HTTPS 核心思路）

```text
非对称传输/协商密钥材料 → 对称（AES）传大数据
= 安全分发 + 高效传输
（旧式 TLS_RSA 是客户端生成预主密钥、服务器公钥解密——"传输"不是双方"协商"）
```

> 陷阱：非对称加密比对称加密慢得多，所以不用它加密全部数据。

## 三、摘要 / 鉴别 / 签名 三角

| 机制 | 用什么 | 解决 | 特点 |
|------|--------|------|------|
| **报文摘要** | 散列函数（MD5/SHA） | 完整性（⚠️ 裸摘要只能检出传输差错，不能防主动篡改） | 单向、不可逆 |
| **报文鉴别码 MAC** | 使用共享密钥生成的鉴别码（散列实现即 HMAC） | 完整性 + 认证 | 双方有密钥 |
| **数字签名** | 私钥对摘要执行签名算法 | 认证 + 完整性 + 不可否认 | 公钥可验证 |

```text
数字签名过程：
  发送方：对报文摘要用私钥执行签名算法 → 签名，附在报文后
  接收方：用公钥验证签名 → 验证通过 = 摘要一致 → 未篡改 + 来自私钥持有者
  （通用签名算法的验证输出是"通过/不通过"，不是"解密得到摘要"）

一句话记：
  摘要 = 指纹
  MAC  = 指纹 + 印章（双方都知道的印章）
  签名 = 指纹 + 私人印章（只有我有）
```

> 陷阱：签名用**发送方私钥**（教学简化说"私钥加密摘要"），不是公钥！
> 陷阱：报文鉴别不能提供不可否认性，数字签名可以。

## 四、HTTPS/TLS 握手（默写级）

```text
① 客户端 → 服务器：支持的加密套件 + 客户端随机数
② 服务器 → 客户端：数字证书 + 选定套件 + 服务器随机数
③ 客户端验证证书（CA 签名、有效期、主机名等）→ 生成预主密钥
   → 用服务器公钥加密（旧式 TLS_RSA 密钥传输）→ 发送
④ 双方用客户端随机数 + 服务器随机数 + 预主密钥（秘密输入）
   → KDF 派生会话密钥
⑤ 之后通信：会话密钥对称加密（完整握手还有 Finished 校验，此处为密钥建立主线）

用到的东西：
  非对称密码：密钥传输（RSA）、证书签名（CA 私钥）、握手身份认证
  对称加密：会话密钥传数据（AES）
  数字签名：CA 签名证书
  散列函数：证书摘要、握手转录校验、KDF
  证书：身份 + 公钥 + CA 签名
```

> 陷阱：HTTPS 用 443 端口；TLS 握手发生在 TCP 建立之后。
> 陷阱：TLS 1.3 已取消 RSA 密钥传输（现代题答"服务器公钥加密预主密钥"是旧口径），改用 (EC)DHE 协商，另有 PSK/PSK-DHE 模式。

## 五、防火墙与攻击

```text
防火墙分层：
  网络层（包过滤）：IP + 端口规则
  应用层（代理）：检查内容

防火墙局限：**不能完全防御**病毒、内部攻击、DoS（应用层/下一代防火墙、
  内部隔离防火墙、ACL/限流可检测或缓解一部分）

攻击速记：
  窃听 → 加密防御
  篡改 → 鉴别/签名防御
  重放 → 序号/时间戳防御
  中间人 → CA 证书防御
  DoS → 防火墙/限流
```

## 六、选择题高频陷阱

| 陷阱说法 | 纠正 |
|---------|------|
| 数字签名用公钥加密 | 发送方**私钥执行签名算法**，公钥验证（RSA 教学简化说"私钥加密摘要"） |
| 非对称加密比对称快 | 相反，对称加密**快得多** |
| 报文鉴别能防抵赖 | 报文鉴别**不能**不可否认，数字签名可以 |
| MD5 是加密算法 | MD5 是**散列函数**（不可逆），不是加密（可逆） |
| 对称加密密钥分发简单 | 对称加密最大问题就是**密钥分发难** |
| HTTPS 全程非对称加密 | 数据用**对称加密**；非对称承担**密钥传输/证书签名/握手身份认证**（现代 TLS 用 (EC)DHE 协商） |
| 防火墙能防病毒 | 传统边界防火墙**不能完全防**病毒（应用层/下一代防火墙可识别部分恶意内容） |
| 公钥加密用公钥解密 | 公钥加密 → **私钥**解密 |

## 七、记忆口诀

```text
加密四件套：机密加密、完整鉴别、认证签名、不可否认靠签名
加密分工：对称快但分发难，非对称慢但分发易，混合起来是王道
签名方向：私钥签名公钥验，公钥加密私钥解
HTTPS：证书验身份，非对称传密钥，对称传数据
```
