# 网络安全：题型训练

> 定位：⚠️ 现行 408 计算机网络大纲**未列出独立网络安全考点**（范围止于应用层）；
> 本层是**教材第 7 章扩展整理**，题型以「概念辨析 + 流程判断」为主，不需要计算，
> 供理解 HTTPS 等应用层机制的原理背景，不按独立考点预测分值。

## 1. 题型总表

| 题型 | 高频考点 | 掌握标准 |
|------|---------|---------|
| 加密体制判断 | 对称 vs 非对称、谁加密谁解密 | 能秒判 |
| 摘要/鉴别/签名 | 三者区别、各自解决什么问题 | 不混淆 |
| HTTPS 流程 | 握手步骤、用到哪些技术 | 能按序默写 |
| 安全目标 | 机密性/完整性/认证/不可否认 | 能配对 |
| 攻击识别 | 窃听/篡改/重放/中间人/DoS | 能选防御 |
| 防火墙 | 分层、局限 | 能判断对错 |

## 2. 必背速记

```text
对称加密：DES/AES，同密钥，快，分发难
非对称加密：RSA，公私钥，慢，分发易
混合体系：非对称传密钥，对称传数据
报文摘要：散列函数（MD5/SHA），单向不可逆，验完整性
报文鉴别码 MAC：使用共享密钥生成的鉴别码（散列实现即 HMAC），验完整性 + 认证
数字签名：发送方私钥执行签名算法（教学简化说法"私钥加密摘要"），验认证 + 完整性 + 不可否认
HTTPS：证书验身份，非对称传预主密钥，对称传数据
防火墙：网络层包过滤 + 应用层代理，**不能完全防御**病毒/内部攻击/DoS（可缓解一部分）
```

## 3. 加密体制题

**判断对称/非对称：**

| 题干 | 答案 |
|------|------|
| DES 属于什么加密？ | 对称加密 |
| AES 属于什么加密？ | 对称加密 |
| RSA 属于什么加密？ | 非对称加密 |
| 公钥加密用什么解密？ | 私钥 |
| 数字签名用什么密钥？ | 发送方私钥执行签名算法（RSA 教学简化说"私钥加密摘要"，DSA/ECDSA 不是加密） |
| 数字签名用什么验证？ | 发送方公钥 |

**辨析题：**

```text
Q: 为什么实际网络通信不全程用非对称加密？
A: 非对称加密慢（数学运算量大），大数据量用对称加密效率高。
   所以用非对称协商密钥 + 对称加密数据。

Q: 对称加密的主要缺点？
A: 密钥分发难（如何安全地让双方共享密钥）、密钥管理成本 O(N²)。
```

## 4. 摘要 / 鉴别 / 签名辨析题

| 题目 | 答案 |
|------|------|
| 报文摘要解决什么问题？ | 完整性（检测篡改）——⚠️ 无认证保护的裸摘要只能检出**传输差错**，主动攻击者可同时修改报文并重算摘要；防主动篡改必须用 MAC（共享密钥）或数字签名（私钥） |
| 摘要用什么算法生成？ | 散列函数（MD5/SHA），单向不可逆 |
| MAC 比摘要多解决什么问题？ | 认证发送方（共享密钥） |
| 数字签名比 MAC 多解决什么问题？ | 不可否认性 |
| 为什么数字签名能防抵赖？ | 签名用私钥生成，只有持有者能生成，公钥可验证 |

**经典真题型（类似 408 考法）：**

```text
Q: 甲向乙发送加密消息，要保证乙能验证消息确实来自甲且未被篡改，
   甲应该怎么做？
A: ① 机密性：用乙的公钥（或双方协商的对称密钥）加密消息内容；
   ② 认证+完整性：甲对消息摘要用甲的私钥执行签名算法（数字签名），附在消息后；
   ③ 乙的操作顺序（签名针对明文摘要时）：先**解密**得到明文 → 重新计算摘要 →
      再**验签**比对（必须先解密才能重新算摘要；只有"对密文签名"的变体才先验签后解密）。
   → 认证（来自甲）+ 完整性（未篡改）+ 不可否认（甲不能抵赖）+ 机密性（只有乙能读）
```

## 5. HTTPS 流程题

**按序默写（旧式 TLS_RSA 密钥交换示例，⚠️ 教学简化）：**

```text
① 客户端发：支持的加密套件 + 客户端随机数
② 服务器回：数字证书 + 选定套件 + 服务器随机数
③ 客户端验证证书 → 生成预主密钥 → 服务器公钥加密 → 发送
④ 双方用客户端随机数+服务器随机数+预主密钥 → KDF 派生会话密钥
⑤ 会话密钥对称加密通信（TLS 同时提供完整性/认证保护）
```

> ⚠️ ③④ 是旧式 TLS_RSA：TLS 1.3 已取消 RSA 密钥传输，改用 (EC)DHE；
> 考题若问现代 TLS，不要答"服务器公钥加密预主密钥"。

**辨析：**

```text
Q: HTTPS 中证书的作用？
A: 证明服务器身份 + 提供服务器公钥（CA 签名保证证书未被篡改；
   还需验证信任链、有效期、主机名、用途）

Q: HTTPS 用到哪几种密码学技术？
A: 非对称密码（密钥传输/证书签名/身份认证）+ 对称加密（会话密钥）
   + 数字签名（CA 签证书）；散列函数用于证书摘要、握手转录校验与 KDF
```

## 6. 攻击识别题

| 场景 | 攻击类型 | 防御 |
|------|---------|------|
| 黑客截获通信数据读取内容 | 窃听 | 加密 |
| 黑客修改传输中的订单金额 | 篡改 | 报文鉴别/签名 |
| 黑客重发之前的转账报文 | 重放 | 序号/时间戳 |
| 黑客冒充银行和用户双方通信 | 中间人 | CA 证书 |
| 攻击者洪泛请求使服务器瘫痪 | DoS | 防火墙/限流 |

## 7. 判断题（陷阱检测）

| 题目 | 答案 |
|------|------|
| 对称加密的密钥分发是最大难题 | 对 |
| 非对称加密比对称加密速度快 | 错 |
| 数字签名用公钥加密报文 | 错，用私钥 |
| MD5 是一种加密算法，可以解密 | 错，散列函数不可逆 |
| 报文鉴别能提供不可否认性 | 错，需要数字签名 |
| 防火墙能完全防止网络攻击 | 错——防火墙**不能完全防御**病毒/内部攻击/DoS，但可缓解部分 DoS（限流/ACL），下一代防火墙可识别部分恶意内容 |
| HTTPS 数据部分用对称加密 | 对 |
| CA 的签名保证证书可信 | ◐ 有条件成立——CA 签名证明证书由相应私钥签发且未被改动；**可信**还要求信任链、有效期、主机名、用途（必要时候吊销状态）均通过检查 |
