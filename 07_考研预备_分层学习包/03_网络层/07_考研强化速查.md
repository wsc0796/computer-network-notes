## 一、ICMP报文完整分类

### 1. 差错报告报文（5种）

| 报文类型 | 触发场景 | 说明 |
|---------|---------|------|
| **目的不可达** | 路由器找不到目的网络/主机 | 代码细分：0网络不可达、1主机不可达、2协议不可达、3端口不可达... |
| **源站抑制** | 路由器/主机拥塞，丢弃数据报 | 已基本废弃（由TCP拥塞控制替代） |
| **超时** | TTL减到0；分片超时未收全 | 代码0=TTL超时, 代码1=分片重组超时 |
| **参数问题** | IP首部字段非法 | 代码0=指针错误, 代码1=缺少必要选项 |
| **重定向** | 路由器发现更优路径 | 通知源主机下一个包发往另一个路由器 |

### 2. 询问/信息报文（2组）

| 报文 | 作用 |
|------|------|
| **回送请求/回答** | Ping用（ICMP类型8/0） |
| **时间戳请求/回答** | 测量网络延迟（类型13/14） |
| 地址掩码请求/回答 | 获取子网掩码（已废弃） |
| 路由器询问/通告 | 发现本网路由器 |

### 3. 不会产生ICMP差错报文的情况（常考）

```
① ICMP差错报文本身出错 → 不再发ICMP
② 目的地址为广播/多播地址的IP数据报
③ 封装在链路层广播帧中的IP数据报
④ 不是IP分片的第一个分片
⑤ 源地址为0.0.0.0的数据报
```

## 二、路由算法深度

### 1. 距离向量(DV)算法 — Bellman-Ford

```
Dx(y) = min{ Cx(v) + Dv(y) }
            v

每个路由器:
 ① 周期性/变化时向邻居发送自己的距离向量
 ② 收到邻居向量 → 更新自己的距离表
 ③ 若某条路由距离缩短，更新并通知邻居
```

**无穷计数问题（Count-to-Infinity）：**

```
    A ── B ── C
    1     1

  初始: A→C: 2 (经B)
  B→C链路断: B发现自己到C不可达
  B等A的更新: A说"我离C=2"(实际上是经B到C)
  B以为A有别的路: B更新到C=1+2=3
  然后A发现B更新了: A更新到C=1+3=4
  ...循环直到16(RIP跳数上限)
```

**解决方法：**
- 毒性逆转（Poison Reverse）：A告诉B"我到C的距离=∞"
- 触发更新（Triggered Update）
- 水平分割（Split Horizon）：不把从邻居学到的路由再告诉该邻居

### 2. 链路状态(LS)算法 — Dijkstra

```
每个路由器:
 ① 发现邻居，测量链路开销
 ② 构造链路状态分组(LSP)
 ③ 洪泛LSP给所有路由器
 ④ 计算到所有节点的最短路径树(SPT)

Dijkstra步骤:
 ① 初始化：N'={u}, D(v)=C(u,v)
 ② 循环：找不在N'中的最小D(w)
 ③ 将w加入N'
 ④ 更新每个邻居v的D(v)=min(D(v), D(w)+C(w,v))
 ⑤ 重复直到所有节点在N'中
```

### 3. DV vs LS 对比

| 特性 | DV (RIP) | LS (OSPF) |
|------|---------|----------|
| 思路 | 我离目标有多远？ | 网络拓扑全貌？ |
| 路由计算 | 分布式：仅知邻居距离向量，逐跳迭代 | 全局拓扑信息，但各路由器仍独立分布式运行 SPF |
| 交换内容 | 距离向量（路由表） | 链路状态（LSP） |
| 交换对象 | 仅相邻路由器 | 洪泛给所有路由器 |
| 收敛速度 | 慢（可能有无穷计数） | 快（知道全局拓扑） |
| 复杂度 | 消息O(N×E) | 计算O(N²) |
| 健壮性 | 低（可能传错） | 高（各自算） |
| 典型协议 | RIP、IGRP | OSPF、IS-IS |

## 三、OSPF深入

### 1. 区域划分

```
                      骨干区域(Area 0)
 ┌─────────────────────────────────────────┐
 │  Area 0 (骨干)                          │
 │  ┌─────┐     ┌─────┐     ┌─────┐      │
 │  │ABR  │──── │ABR  │──── │ABR  │      │
 │  └──┬──┘     └──┬──┘     └──┬──┘      │
 └────┼──────────┼──────────┼─────────────┘
      │          │          │
 ┌────┴──┐  ┌───┴───┐ ┌───┴────┐
 │Area 1  │  │Area 2 │ │  Area 3│
 └────────┘  └───────┘ └────────┘
```

| 路由器类型 | 作用 |
|-----------|------|
| 内部路由器(IR) | 所有接口在同一区域 |
| 区域边界路由器(ABR) | 连接骨干区域和其他区域 |
| 骨干路由器(BR) | 至少一个接口在骨干区域 |
| 自治系统边界路由器(ASBR) | 连接其他AS |

### 2. LSA类型

| 类型 | 名称 | 描述 |
|:---:|------|------|
| 1 | 路由器LSA | 本路由器链路状态，区域内洪泛 |
| 2 | 网络LSA | DR生成，描述该网段所有路由器 |
| 3 | 网络汇总LSA | ABR生成，告知其他区域本区域路由 |
| 4 | ASBR汇总LSA | ABR生成，告知ASBR位置 |
| 5 | AS外部LSA | ASBR生成，引入外部路由 |

### 3. DR/BDR选举

```
┌─ 广播型多路访问网络 ─┐
│                      │
│  DR ← 负责收集和分发   │
│  BDR ← DR备份         │
│  DROther ← 只与DR/BDR建立Full邻接（但仍与其他路由器收发 Hello 保持邻居关系）
│                      │
└──────────────────────┘

选举规则：优先级高者胜 (0-255, 默认1)
        优先级相同 → Router ID大者胜
        优先级=0 → 不参与选举
```

### 4. 邻居建立过程

```
Down → Init → 2-Way → ExStart → Exchange → Loading → Full
         ↓                        ↓                     
     收到Hello                  DD报文协商          LSR/LSU/LSAck
     含自己Router ID            主从关系            完整LSA同步
```

> Hello间隔：10s(广播型)/30s(非广播)
> Dead间隔：40s/120s

## 四、BGP

### 1. 基本概念

| 概念 | 说明 |
|------|------|
| AS (自治系统) | 同一管理机构下的网络集合 |
| eBGP | 不同AS之间的BGP会话 |
| iBGP | 同一AS内部的BGP会话 |
| AS号 | 16bit（私有 64512-65534，65535 保留）/ 32bit（私有 4200000000-4294967294） |

### 2. 路径属性

| 属性 | 类型 | 说明 |
|------|:---:|------|
| AS_PATH | 公认必遵 | 经过的AS序列，防环 |
| NEXT_HOP | 公认必遵 | 下一跳路由器IP |
| LOCAL_PREF | 公认可选 | 本地优先级，**高优先**，只在本AS内传 |
| MED | 可选非过渡 | 多出口区分，**低优先**，传递给邻居AS |
| Community | 可选过渡 | 打标记 |

### 3. 选路原则（顺序）

```
① LOCAL_PREF 最高
② AS_PATH 最短
③ MED 最低
④ eBGP > iBGP （倾向于eBGP路径）
⑤ 到NEXT_HOP的IGP路径最短
⑥ 如果都还相同，选最老的BGP路由
```

### 4. BGP vs OSPF vs RIP

| 特性 | RIP | OSPF | BGP |
|:---:|:---:|:----:|:---:|
| 协议类型 | 内部网关(IGP) | 内部网关(IGP) | **外部网关(EGP)** |
| 算法 | 距离向量 | 链路状态 | **路径向量** |
| 度量 | 跳数 | 开销(Cost) | 多种属性 |
| 适用范围 | 小型网络 | 中大型网络 | 互联网核心 |
| 收敛 | 慢 | 快 | 适中 |
| 传输层 | UDP 520 | IP 89(直接) | **TCP 179** |
| 防环 | 跳数上限(16) | SPF树 | AS_PATH |

## 五、IPv6深入

### 1. 地址分类

| 类型 | 前缀 | 说明 |
|------|:----:|------|
| 单播 | 2000::/3 | 全球单播地址 |
| 本地链路 | fe80::/10 | 同一链路通信，不可路由 |
| 唯一本地 | fc00::/7 | 类似IPv4私有地址 |
| 多播 | ff00::/8 | 对应IPv4多播 |
| 任播 | （从单播空间分配）| 任意一个接收（最近原则）|
| 未指定 | :: | 对应0.0.0.0 |
| 回环 | ::1 | 对应127.0.0.1 |

### 2. IPv4 vs IPv6 逐项对比

| 对比项 | IPv4 | IPv6 |
|:-----:|:-----|:-----|
| 地址长度 | 32bit | **128bit** |
| 地址表示 | 点分十进制 | **冒号十六进制** |
| 首部长度 | 可变(20-60B) | **固定40B** |
| 首部校验和 | 有 | **无**（依赖下层/上层校验）|
| 分片 | 路由器可分片 | **路由器不分片**（源主机PMTUD）|
| NAT | 广泛使用 | 理论上不需要 |
| IPsec | 可选 | 标准体系支持 IPsec（通信不会自动加密，是否启用由部署决定） |
| 广播地址 | 有 | **无广播**，用多播替代 |
| 选项 | 首部中 | **扩展首部**（链式）|
| ARP | 有 | **NDP(邻居发现协议)** 替代 |
| IGMP | 有 | **MLD(多播监听发现)** 替代 |

### 3. 过渡技术

| 技术 | 原理 | 场景 |
|------|------|------|
| **双栈** | 同时运行IPv4和IPv6协议栈 | 最常用 |
| **隧道** | IPv6数据报封装在IPv4中传输 | IPv6孤岛跨越IPv4网络 |
| **NAT-PT** | IPv6和IPv4地址转换 | 已基本被NAT64替代 |

## 六、SDN基本概念

### 1. 控制面与数据面分离

```
传统网络:                    SDN:
┌──────────┐               ┌──────────────┐
│ 路由器整合   │               │ SDN控制器(控制面)│
│ 控制面+数据面│               │ OpenFlow协议    │
│ ┌──────┐ │               └──────┬───────┘
│ │路由表 │ │                    │
│ │转发表 │ │               ┌────┴───────┐
│ └──────┘ │               │ 交换机(数据面)│
└──────────┘               │ 仅转发       │
                           └────────────┘
```

| 概念 | 说明 |
|------|------|
| 控制面 | 计算路由、填充转发表（逻辑集中） |
| 数据面 | 根据转发表高速转发（分布） |
| OpenFlow | 南向接口协议，控制器↔交换机 |
| 北向接口 | 应用层↔控制器（REST API等） |

### 2. OpenFlow流表项

```
匹配字段(12元组): 入端口、源MAC、目的MAC、以太网类型、VLAN ID、
                源IP、目的IP、IP协议、TCP/UDP源端口、TCP/UDP目的端口...

动作: 转发到端口、丢弃、封装发送给控制器、修改字段...

计数器: 每流统计(包数、字节数)
```

## 八、NAT深入

### 1. NAT类型

| 类型 | 转换粒度 | 说明 |
|:---:|---------|------|
| 静态NAT | 1个内网IP↔1个公网IP | 固定映射 |
| 动态NAT | N个内网IP映射到M个公网IP(M<N) | 动态分配池 |
| **NAPT** | IP+端口映射（最常见的NAT）| 一个公网IP+端口区分多个内网主机 |

### 2. NAPT示例

```
主机A(192.168.1.2:3345) → 路由器 → 服务器(202.10.1.1:80)
                                ↓
NAT表: (192.168.1.2, 3345) ↔ (203.0.113.1, 50001)
        (192.168.1.3, 3345) ↔ (203.0.113.1, 50002)

外部看到来源都是203.0.113.1, 用端口50001/50002区分
```

### 3. NAT穿透

| 技术 | 原理 |
|------|------|
| 静态端口转发 | 管理员手动配置 |
| UPnP (IGD) | 内网主机自动请求端口映射 |
| STUN/TURN | 应用层NAT穿越协议 |
| 打洞(Hole Punching)| 通过已知服务器协调建立直连 |

## 九、移动IP

| 组件 | 说明 |
|------|------|
| 归属网络 | 移动节点的永久网络 |
| 外部网络 | 移动节点当前访问的网络 |
| 归属代理 | 连接在归属网络上的路由器 |
| 外部代理 | 连接在外部网络上的路由器 |
| 转交地址 | 移动节点在外部网络的临时IP |

**通信过程：**
```
① 移动节点在外部网络获得转交地址
② 向归属代理注册转交地址
③ 归属代理截获发给移动节点的数据报
④ 隧道转发至转交地址
⑤ 外部代理解封装，交付移动节点
⑥ 移动节点发回的响应可直连源主机
```

## 十、路由器结构

```
              ┌────→ 路由选择协议(RIP/OSPF/BGP)
              │           │
              │     ┌─────┴─────┐
              │     │  路由表    │
              │     └─────┬─────┘
              │           │
输入端口 ────→┼─→ 转发表 ←───┘
  ┌──────┐    │    │
  │线路端接│───→ 查表→ ─→ 交换结构
  └──────┘    │    ↑       │
              │    │       ↓
              │    └── 输出端口
              │       ┌──────┐
              │       │线路端接│───→
              │       └──────┘
              │
```

| 组件 | 功能 |
|------|------|
| 输入端口 | 物理层端接、数据链路层处理、查转发表 |
| 交换结构 | 经内部网络将分组从输入传至输出（共享总线/纵横/内存）|
| 输出端口 | 缓存、数据链路层封装、物理层发送 |
| 路由处理器 | 运行路由协议，计算路由表，导出转发表 |

> **路由表 vs 转发表**：路由表含完整路由信息（下一跳、度量等）；转发表是精简版，只包含转发的必要字段

## 十一、选择题高频陷阱

| 陷阱说法 | 纠正 |
|---------|------|
| ICMP封装在UDP中 | ✗ ICMP直接封装在**IP**中 |
| OSPF是距离向量协议 | ✗ OSPF是**链路状态**协议 |
| BGP使用UDP传输 | ✗ BGP使用**TCP 179** |
| IPv6路由器可以分片 | ✗ IPv6中路由器**不分片** |
| IPv6有广播地址 | ✗ IPv6**没有广播**，用多播替代 |
| NAT是解决地址耗尽的根本措施 | ✗ 根本措施是**IPv6**，NAT只能延缓 |
| 组播地址属于D类(224-239) | ✓ 正确 |
| OSPF使用UDP传输 | ✗ OSPF**直接封装在IP**(协议号89) |
| RIP每30s更新一次 | ✓ 正确 |
| 同一个IP地址和掩码反码与运算=主机地址 | ✓ 正确 |
| IP分片的重组由路由器完成 | ✗ 重组由**目的主机**完成 |
| 子网划分增加可用IP总数 | ✗ 子网划分**减少**可用IP总数（消耗网络号和广播地址）|
