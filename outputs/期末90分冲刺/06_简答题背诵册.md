# 06 简答题背诵册

使用方法：每题都按“题目 -> 关键词链 -> 编号评分点 -> 标准答案 -> 30秒口述版”来背。考试时先写关键词链，再按编号评分点展开。

## 1. 题目：流量控制与拥塞控制有什么区别

关键词链：保护对象不同、依据不同、窗口不同、作用位置不同、发送窗口取最小值。

评分点：

1. 流量控制的目标是防止发送方把接收方缓存冲垮。
2. 拥塞控制的目标是防止过多数据注入网络导致网络拥塞。
3. 流量控制主要依据接收方通告窗口 `rwnd`。
4. 拥塞控制主要依据拥塞窗口 `cwnd` 和网络状态。
5. 流量控制体现为端到端接收能力匹配。
6. 实际发送窗口通常取 `min(rwnd, cwnd)`。

标准答案：流量控制和拥塞控制解决的问题不同。流量控制保护接收方，避免发送过快导致对方缓存溢出，主要依据接收方通告窗口 `rwnd`。拥塞控制保护网络，避免链路和路由器过载，主要依据拥塞窗口 `cwnd`、丢包和时延等网络状态。实际发送窗口通常取 `min(rwnd, cwnd)`，因此二者会共同限制发送方速度。

30秒口述版：流量控制看接收方，核心是 `rwnd`；拥塞控制看网络，核心是 `cwnd`；真正能发多少取二者最小值。

易丢分点：把 `rwnd` 和 `cwnd` 写反；只写“一个保护主机一个保护网络”，没写发送窗口关系。

预计分值：6分

## 2. 题目：简述慢开始、拥塞避免、快重传、快恢复

关键词链：慢开始翻倍、达到门限线性、三次重复ACK快重传、Reno快恢复、超时回1。

评分点：

1. 慢开始阶段 `cwnd < ssthresh`，通常每经过1个RTT近似翻倍。
2. 达到门限后进入拥塞避免，`cwnd` 每个RTT近似加 1 MSS。
3. 收到 3 个重复 ACK 时触发快重传，不必等待超时。
4. 题目明确按 TCP Reno 时，进入快恢复先令 `ssthresh = 当前cwnd/2`。
5. TCP Reno 快恢复入口令 `cwnd = ssthresh + 3 MSS`，收到新的确认后令 `cwnd = ssthresh` 并进入拥塞避免。
6. 超时说明拥塞更严重，`ssthresh = 当前cwnd/2`，`cwnd = 1 MSS`，重新慢开始。

标准答案：TCP 拥塞控制包括慢开始、拥塞避免、快重传和快恢复。慢开始中，当 `cwnd < ssthresh` 时，`cwnd` 通常按 RTT 指数增长；达到门限后进入拥塞避免，`cwnd` 转为线性增长。若收到 3 个重复 ACK，发送方立即执行快重传。若题目明确采用 TCP Reno，则进入快恢复时令 `ssthresh = 当前cwnd/2`，`cwnd = ssthresh + 3 MSS`；当收到确认新数据的 ACK 后，再令 `cwnd = ssthresh`，进入拥塞避免。若发生超时，则认为拥塞更严重，令 `ssthresh = 当前cwnd/2`，`cwnd = 1 MSS`，重新慢开始。

30秒口述版：慢开始翻倍，拥塞避免加一；3个重复ACK先快重传；明确按Reno就 `ssthresh` 减半、`cwnd=ssthresh+3MSS` 进快恢复；超时最重，`cwnd` 回 1。

易丢分点：把快恢复写成“约减半”；没写超时和3重复ACK的区别。

预计分值：6分

## 3. 题目：停止等待、GBN、SR有什么区别

关键词链：窗口大小、确认方式、乱序处理、重传范围、编号空间限制。

评分点：

1. 停止等待任意时刻只允许一个未确认帧，效率最低。
2. GBN 是多帧滑动窗口，接收方通常只按序接收。
3. GBN 采用累计确认，`ACK=k` 表示 `k` 之前已按序收到，下一步期待 `k`。
4. GBN 出错后通常从出错帧开始回退重传。
5. SR 允许接收方缓存乱序帧，只重传丢失或出错帧。
6. SR 的发送窗口和接收窗口通常都不超过序号空间的一半。

标准答案：停止等待协议一次只能发送一个未确认帧，发送方必须等确认后才能继续发送。GBN 和 SR 都属于多帧滑动窗口协议。GBN 采用累计确认，接收方通常只接收按序到达的帧；若某帧丢失，发送方会从该帧开始回退重传。SR 则允许接收方缓存乱序帧，对每个正确帧分别确认，发送方只重传真正丢失或出错的帧。为避免新旧序号混淆，SR 的窗口大小通常不超过序号空间的一半。

30秒口述版：停止等待最保守；GBN 能连发但丢一个要从它开始回退；SR 能缓存乱序，只补丢的那几个。

易丢分点：把 GBN 写成“只重传丢失帧”；把 `ACK=k` 理解成“已经收到 k 号帧本身”。

预计分值：6分

## 4. 题目：简述RIP工作原理

关键词链：距离向量、跳数、周期更新、加1、同一下一跳更新、16不可达。

评分点：

1. RIP 是距离向量路由协议。
2. RIP 以跳数作为度量。
3. 路由器周期性交换自己的路由表。
4. 收到邻居通告后，距离必须先加 1 再比较。
5. 如果来自同一下一跳，即使距离变差也要更新。
6. 跳数达到 16 视为不可达。

标准答案：RIP 属于距离向量路由协议，使用跳数作为度量。各路由器周期性向邻居发送自己的路由表。收到邻居的某条路由后，要先把该距离加 1，再与本地路由表比较。若是新的目的网络就加入；若通过不同下一跳且更短则替换；若来自同一下一跳，即使距离变差也要更新。RIP 规定最大有效跳数为 15，16 表示不可达。

30秒口述版：RIP 就是“把到各网的跳数告诉邻居”；邻居收到后先加 1，再比较；同一下一跳变差也得改；16 就当断路。

易丢分点：忘记“先加1”；忘记“同一下一跳变差也更新”。

预计分值：6分

## 5. 题目：TCP与UDP有什么区别

关键词链：连接、可靠、有序、字节流、报文边界、首部、控制机制。

评分点：

1. TCP 面向连接，UDP 无连接。
2. TCP 提供可靠传输，UDP 只提供尽力交付。
3. TCP 保证按序到达，UDP 不保证按序。
4. TCP 面向字节流，UDP 面向报文。
5. TCP 有流量控制和拥塞控制，UDP 一般没有。
6. TCP 首部较大，UDP 首部固定 8 字节。

标准答案：TCP 面向连接，建立连接后提供可靠、按序的字节流服务，并具有流量控制和拥塞控制等机制，首部开销较大。UDP 无连接，只提供尽力交付，不保证可靠性和顺序，保留报文边界，首部固定 8 字节，适合对实时性要求较高或实现简单的场景。

30秒口述版：TCP 有连接、可靠、有序、字节流，还管流量和拥塞；UDP 无连接、尽力交付、保留报文边界，首部只有 8 字节。

易丢分点：把 UDP 写成“完全不校验”；把“字节流”和“报文”写反。

预计分值：6分

## 6. 题目：TCP三次握手为什么不能改成两次

关键词链：确认双向能力、旧SYN、误建连接、初始序号确认。

评分点：

1. 第一次报文用于客户端发起连接请求。
2. 第二次报文用于服务器确认客户端请求并同步自己的初始序号。
3. 第三次报文用于客户端确认服务器的发送与接收能力正常。
4. 三次握手能够确认双方都具备收发能力。
5. 如果只有两次，服务器无法确认客户端是否收到了自己的确认。
6. 三次握手还能防止失效连接请求报文突然到达而误建连接。

标准答案：TCP 采用三次握手是因为建立连接时需要确认双方的发送能力、接收能力以及初始序号同步情况。若只有两次，服务器虽然能收到客户端的连接请求，但无法确认客户端是否收到了自己的确认报文，也无法可靠避免网络中失效的旧连接请求报文突然到达所带来的误建连接问题。第三次 ACK 正是为了解决这一点。

30秒口述版：两次只能保证“我收到你了”，三次才能保证“我收到你、你也收到我”；同时还能挡住失效旧 SYN 造成的误连接。

易丢分点：只写“防止旧连接”，没写双方收发能力确认。

预计分值：6分

## 7. 题目：简述四次挥手与TIME_WAIT

关键词链：全双工、半关闭、两个方向分别关、最后ACK、2MSL。

评分点：

1. TCP 是全双工连接，两个方向要分别关闭。
2. 主动关闭方先发送 FIN。
3. 对方收到 FIN 后先回 ACK，此时连接处于半关闭。
4. 对方数据发完后再发送 FIN。
5. 主动关闭方回最后一个 ACK 后进入 TIME_WAIT。
6. TIME_WAIT 持续 2MSL，用于保证最后 ACK 可重传并让旧报文从网络中消失。

标准答案：TCP 连接是全双工的，因此释放连接时两个传输方向要分别关闭。主动关闭方先发送 FIN，对方收到后回 ACK，此时只关闭了一个方向，另一个方向仍可继续发送数据；等对方数据发送完后，再发送自己的 FIN。主动关闭方回最后一个 ACK 后进入 TIME_WAIT，持续 2MSL，以保证最后 ACK 丢失时还能重传，同时让旧连接中的报文在网络中自然消失。

30秒口述版：四次挥手是因为双向都要各关一次；中间有半关闭；最后主动关闭方进 TIME_WAIT，等 2MSL 保最后 ACK 和清旧报文。

易丢分点：把四次挥手写成三次；不解释 TIME_WAIT 的作用。

预计分值：6分

## 8. 题目：简述CSMA/CD的工作过程

关键词链：先听后发、边发边听、冲突停止、发送干扰、指数退避。

评分点：

1. 发送前先监听信道是否空闲。
2. 空闲才发送，忙则等待。
3. 发送时继续监听，即边发边听。
4. 一旦检测到冲突，立即停止发送。
5. 发送干扰信号，让其他站点也知道发生了冲突。
6. 经过二进制指数退避后再重传。

标准答案：CSMA/CD 用于传统共享式有线以太网。站点发送前先监听信道，若空闲则发送，若忙则等待；发送过程中继续监听信道，即边发边听。若检测到冲突，就立即停止发送并发送干扰信号，然后按照二进制指数退避算法等待随机时间，再尝试重传。

30秒口述版：CSMA/CD 就是“先听后发，边发边听，冲突就停，退避再发”。

易丢分点：漏掉“边发边听”或“干扰信号”；把它写到无线局域网场景里。

预计分值：6分

## 9. 题目：简述交换机自学习过程

关键词链：源MAC学习、入端口绑定、目的MAC查表、未知泛洪、老化。

评分点：

1. 交换机收到帧后先读取源 MAC 地址。
2. 把源 MAC 与入端口写入或更新到交换表。
3. 再读取目的 MAC 地址查找交换表。
4. 若已知目的端口，则定向转发。
5. 若未知目的端口，则除入端口外泛洪。
6. 表项会随时间老化删除。

标准答案：交换机具有自学习功能。收到帧后，它先根据源 MAC 地址和帧进入的端口建立或更新交换表项；然后根据目的 MAC 地址查表，若找到对应端口，就只向该端口转发；若没有找到，就向除入端口外的其他端口泛洪。为了适应网络变化，交换表项会在一定时间后老化删除。

30秒口述版：交换机先看源地址学表，再看目的地址转发；不知道目的在哪时就泛洪；旧表项会老化。

易丢分点：把“源MAC学习”写成“源IP学习”；把未知目的写成直接丢弃。

预计分值：6分

## 10. 题目：ARP与DHCP分别做什么，过程有什么不同

关键词链：ARP求MAC、DHCP分配配置、广播请求、单播响应、DORA。

评分点：

1. ARP 用于根据 IP 地址获得同一链路内的 MAC 地址。
2. DHCP 用于动态获取 IP 地址和其他网络配置。
3. ARP 请求通常是广播。
4. ARP 响应通常是单播。
5. DHCP 典型过程为 Discover、Offer、Request、ACK。
6. 两者分属不同任务：ARP解决链路层寻址，DHCP解决主机入网配置。

标准答案：ARP 和 DHCP 的作用不同。ARP 用于在同一链路内根据目标 IP 地址解析得到目标主机或下一跳的 MAC 地址，ARP 请求通常以广播发送，响应通常是单播。DHCP 用于主机自动获取 IP 地址、子网掩码、默认网关等网络参数，其典型过程为 Discover、Offer、Request、ACK。前者解决“发给谁的 MAC”，后者解决“我自己的地址和配置是什么”。

30秒口述版：ARP 是“拿 IP 去问 MAC”；DHCP 是“主机刚入网时给自己领 IP 和配置”；ARP 请求广播、响应单播，DHCP 走 DORA。

易丢分点：把 ARP 和 DHCP 都写成“分配地址”；忘记 DORA 四步。

预计分值：6分
